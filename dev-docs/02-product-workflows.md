# 화면과 업무 흐름

## 실제 제품: 공유 프로젝트

Home은 활성 작성용 LLM과 공용 판정 연결의 설정 상태를 먼저 확인한다. 빠진 역할이 있으면 해당 Admin 화면에 안내를 표시하고, 두 역할 모두 설정되면 공용 프로젝트 갤러리를 연다. Admin 인증 전에는 두 역할의 설정 여부만 조회한다. 데스크톱 3열, 중간 화면 2열, 휴대전화 1열로 배치하며 한 페이지에 6개를 표시한다. 이름 검색·마감일 한 날짜 선택·진행 중/보관됨/전체·최근 변경/마감일/이름 정렬은 API에서 처리한다. 적용된 필터와 페이지는 URL에 남아 뒤로 가기로 복원된다.

Home 상단의 `프로젝트 만들기` 버튼, 카드와 빈 영역의 우클릭 메뉴에서 등록한다. 이름과 마감일은 필수이며 마감일은 shadcn 달력으로 선택한다. 카드는 저장된 이름·상태·마감일·D-Day·생성일·수정일을 표시한다. 문서·PPT 수를 임의로 만들지 않는다.

점 세 개·우클릭·Shift+F10으로 메뉴를 연다. 이름 바꾸기, 프로젝트 정보 복사, 보관/복원, 삭제를 제공한다. 정보 복사는 이름·마감일을 등록 폼에 채운 뒤 새로운 빈 프로젝트를 만든다. 문서·가이드·PPT 전체 복제는 미구현이다. 삭제 확인은 모든 접속자의 목록에서 숨기며 DB 행과 요청 기록을 보존한다. 보관은 복원할 수 있지만 삭제 취소·물리 정리 UI는 아직 없다.

생성·이름 변경·상태 변경·삭제는 shadcn Dialog/Alert Dialog에서 수행한다. 실패하면 입력과 대상을 유지한다. 변경 충돌 시 최신 정보를 명시적으로 읽고 검토한 후 다시 실행한다. 목록은 loading·empty·error·갱신 상태를 구분하며 마지막 페이지의 항목이 사라지면 유효한 페이지로 이동한다.

다른 접속자의 변경은 수동 갱신, 포커스 복귀 또는 15초 갱신으로 확인한다. 서버를 재시작해도 SQLite의 프로젝트는 유지된다. 사용자가 누구인지 기록하거나 개인별 프로젝트 목록을 분리하지 않는다.

현재 제품 메뉴는 Home·Studio·Space·Admin을 제공한다. Admin은 일반·LLM 연결·Decision Model 연결을 제공하고 기존 `/home/system` 상태 확인 경로는 별도로 유지한다. Studio의 원본 등록·작성 방향은 실제 구현이며, 나머지 단계의 구현 범위는 아래 기능별 설명을 따른다.

## Space 제품 흐름

`/home/space`는 **전체 | 레퍼런스 | 템플릿** 순서이며 기본 진입은 전체다. 전체는 두 종류를 서버에서 함께 정렬·검색·페이지 분할한다. 카드에는 종류를 표시하며, 전체의 자료 올리기 메뉴에서 등록할 종류를 선택한다. 개별 탭은 해당 종류로 바로 업로드한다. 레퍼런스는 PDF/HWP/HWPX/DOCX/PPTX/XLSX/HTML/HTM, 템플릿은 PPTX를 받는다. 입력 창은 한 번에 10개, 파일당 50 MiB를 안내한다. 이름과 태그는 선택이며 프로젝트 원본으로 자동 연결하지 않는다.

상단 종 아이콘은 제공하지 않는다. 우측 하단 작업 패널이 이 탭의 전송 대기·진행률·서버 확인·완료·실패를 표시한다. 접으면 요약, 닫으면 작은 작업 보기 버튼으로 바뀌고 어느 동작도 전송을 취소하지 않는다. 새 업로드는 상세 패널을 다시 연다. 실패 재시도·서버 확인 후 취소·완료 항목 정리를 유지하며 Home에서도 같은 작업을 확인한다. 다른 브라우저/탭에는 공유하지 않고 등록 자산만 공용 목록에 반영한다. 새로고침 시 대기열은 초기화되며 바이트 이어받기는 제공하지 않는다.

갤러리는 3/2/1열, 페이지당 12개이며 이름·파일명·태그 검색과 활성/보관됨/전체 필터를 제공한다. 더보기 메뉴에서 정보 수정, 새 파일 버전, 버전별 원본 다운로드, 보관/복원, 논리 삭제를 실행한다. 동시 수정 충돌 시 작성 내용을 유지하고 최신 정보를 확인한 후 재시도한다. 목록은 15초 간격·창 포커스·수동 갱신으로 공유 변경을 반영한다.

원본 바이트와 이전 파일 버전은 보존된다. 처리 결과 보기에서 실제 추출·판정 결과를 제공한다. 파일 추천·의미 검색은 아직 없다.

문서 처리의 의미 분류는 System One 형태의 `state + questions`를 받는 판정 경계로 설계한다. 초기 LLM 구현은 `choice`의 `"0"`/`"1"`을 반환하고 서버가 schema와 대상 블록 연결을 검증해 `is_table_of_contents` 정수로 변환한다. 독립 질문은 배치로 묶고 자유 텍스트 목차 추출은 분리해 향후 native Jev 연결이 가능하도록 한다. LLM 응답에 Jev의 확률을 꾸며 넣지 않는다. 실패·미판정은 `0`으로 처리하지 않는다. [판정 계약](../blueprint/04-workflow-engine.md)과 [어댑터 계약](../blueprint/06-llm-admin.md#system-one-형태의-decision-adapter)의 추출 리비전·설정 고정·결과 재사용 규칙을 따른다. 원본 블록 분류·영속 Worker도 연결되어 있으며 실제 Jev 계정 검증은 미완료다. 업로드 완료는 분석 완료를 뜻하지 않는다.

종류를 바꾸면 검색어·상태는 유지하고 첫 페이지로 돌아간다. URL 뒤로 가기는 선택한 종류를 복원한다. HTML/HTM은 UTF-8 원본 등록·버전·다운로드를 지원한다. Markdown/MD는 아직 허용하지 않는다. HWP 5.x/HWPX는 Kordoc 추출과 가능한 원본 페이지 PNG를 제공한다. Office/HWP의 PDF 정규화는 별도 후속 범위다.

HTML은 최대 50 MiB이며 UTF-8 BOM도 허용한다. 다른 인코딩은 UTF-8로 저장 후 재업로드하도록 안내한다. 브라우저와 같은 HTML 문법 복구를 허용하되 단순 텍스트·주석만 있는 파일은 등록하지 않는다. HTML은 본문을 추출하되 앱 내 원본 HTML 실행·PDF 변환은 제공하지 않으며 원본을 변형하거나 스크립트·외부 리소스를 실행하지 않는다.

## Admin 제품 흐름

`/home/admin`은 CLI 토큰으로 진입하는 팀 공용 관리 화면이다. Admin 전용 사이드 메뉴에서 모델 연결·문서 처리·시스템 상태를 선택한다. 등록된 연결의 상세는 연결 설정·처리 설정·연결 테스트·판정 테스트·요청 이력으로 구성한다. 시스템 상태는 실제 Health API의 연결·버전 정보이며 상세 DB/OCR 진단은 미구현이다.

모델 조회는 저장 전에 가능하다. 저장 후 텍스트·구조화·판정 테스트는 별도 명시적 동작이며 짧은 고정 샘플만 보내고 업로드 문서는 보내지 않는다. 현재 설정 버전, 응답, 소요 시간, 제공된 토큰 수와 최근 20건의 요청 이력을 표시한다.

새 설정이 저장되면 다음 요청부터 적용하고 진행 중인 요청은 시작 당시 버전을 유지한다. 수정 충돌은 입력을 보존하며 최신 설정을 확인한 뒤 다시 저장한다. API Key는 유지·교체·삭제를 명시적으로 선택하고 저장된 키 원문은 표시하지 않는다. 비활성 연결은 테스트할 수 없다.

응답 대기 중단 또는 화면 이탈은 브라우저 요청을 취소한다. 이미 서버로 전달된 추론은 제한 시간까지 계속될 수 있으며 중단 안내에 이 차이를 표시한다. 모델 목록이 있어도 Vision·Tool Calling·문서 처리까지 지원한다고 표시하지 않는다.

Provider를 선택하면 해당 방식의 기본 주소와 안내를 적용하고 모델 ID·인증 정보를 재확인한다. 선택만으로 저장하거나 테스트하지 않는다. 기존 연결의 종류를 바꿀 때 저장된 키를 다른 인증 방식에 자동 재사용하지 않는다. LM Studio Native에서는 구조화 테스트 버튼을 비활성화하고 미지원 이유와 명시적 호환 연결 선택 경로를 안내한다.

Admin의 section/provider/tab은 URL 검색 파라미터로 관리한다. 예: `/home/admin?section=providers&provider=<id>&tab=history`, `/home/admin?section=system`. 새로고침과 뒤로 가기로 선택을 복원한다. 테스트 패널을 다른 상세 탭으로 전환해도 요청 대기와 결과를 유지하며, Admin의 다른 메뉴로 이동하면 해당 화면의 요청 대기를 정리한다. 사이드 메뉴는 데스크톱·모바일에서 접고 다시 펼칠 수 있다. 기존 `/home/system` 경로도 같은 서비스 상태 기능을 재사용한다.

LLM 또는 Decision 탭에서 Provider를 선택한다. Provider를 전환하면 해당 연결의 입력을 열고 기본 주소를 안내하며 모델은 조회 결과에서 선택한다. System One에는 TypeSafe·LM Studio·llama.cpp·SGLang·vLLM·LiteLLM·OpenAI·Gemini의 확인된 판정 경로를 제공한다. Claude는 전용 판정 API를 확인하지 못했으므로 LLM 연결로만 제공한다.

판정 테스트는 사용자가 검토한 내용과 choice 질문 JSON을 한 번에 전송한다. 초기 목차 예시는 실행 전 로컬 샘플이며 실제 파일을 가져오지 않는다. 오류는 제출 후 표시하고 입력을 유지한다. 재시도는 명시적 재실행이다. 실행 중에는 draft를 잠그며, 수정 시 이전 결과를 지워 새 입력의 결과처럼 보이지 않게 한다. 같은 설정의 탭 이동은 결과를 유지하고 설정 변경·화면 이탈은 대기를 정리한다. 네이티브 결과의 확률은 Provider 보고값이고 LLM 결과에는 확률을 표시하지 않는다. Space 레퍼런스 자동 처리는 문서 처리 메뉴에서 선택한 연결을 사용한다. 그 외 작업별 라우팅은 아직 없다.

## 실제 문서 처리 흐름

업로드 목적이 처리 경로를 결정한다. **템플릿 업로드는 PPT Master 템플릿 분석만 수행**하며 Kordoc 내용 추출이나 목차 판정을 실행하지 않는다. 원본 PPTX, 마스터·레이아웃·슬롯 등의 manifest, native structure, 재사용 자산 번들을 보존한다. 분석 번들은 원본 PPTX를 중복 포함하지 않으며 원본은 기존 다운로드로 제공한다. 슬롯 편집·생성에 템플릿 적용·완성 PPTX 왕복 검증은 별도 기능이다.

**레퍼런스는 파일 형식 확인 → PPTX 여부 확인 → 본문·이미지 추출과 재사용 자료 준비 → 목차 판정** 순서다. PPTX는 PPT Master로 원본 장표·이미지·그룹 도식·차트·표의 네이티브 구조와 미리보기를 추가 준비한다. PPTX 판별은 업로드 검사 결과를 사용하며 LLM을 호출하지 않는다. 레퍼런스 PPTX를 템플릿으로 자동 추출하거나 공용 템플릿에 등록하지 않는다. 템플릿으로 분석하려면 템플릿 종류로 별도 등록하며 원본 바이트는 해시로 중복 제거한다.

문서 읽기 도구의 실행 제한은 호출당 30분이다. PDF는 본문·OCR·블록 추출과 페이지 미리보기 생성을 한 호출에서 수행한다. PPTX는 슬라이드 가져오기, 슬라이드 미리보기, 재사용 객체 추출·미리보기를 별도 도구로 실행한다. 서버 로그의 `job_id`, `step`, `elapsed_ms`로 각 호출의 경과 시간을 확인할 수 있다. 목차 판정은 추출 결과 저장 후 별도 단계에서 실행되며 모델 연결의 요청 제한 시간을 따른다.

새 파일 버전 등록과 최초 처리 작업은 같은 SQLite 트랜잭션으로 확정한다. 기존 파일은 자동 소급 분석하지 않으며 카드의 미리보기에서 명시적으로 준비를 요청한다. 파일 교체는 새 원본 버전의 새 작업을 만들고 이전 결과를 유지한다. 자료 삭제는 진행·대기 작업을 함께 취소하고 원본과 결과의 물리 삭제는 하지 않는다.

레퍼런스는 HTML의 수동 실행 없는 텍스트 추출과 Kordoc의 PDF/HWP/HWPX/DOCX/PPTX/XLSX 추출을 사용한다. PDF의 스캔·필요 페이지에는 번들된 PP-OCRv5 한국어 인쇄체 모델을 사용한다. PNG 원본 미리보기는 PDF 및 렌더 가능한 HWP/HWPX에서 제공한다. Office 파일은 블록·이미지와 가능한 슬라이드/시트/조판 위치를 제공하며, 페이지 미리보기가 없는 형식은 그대로 안내한다. HTML 외부 이미지·스크립트·원격 리소스는 가져오지 않는다.

레퍼런스 화면은 준비 상태·재시도, 페이지/영역 선택, 최대 50개씩 본문 조회·검색, 표 텍스트·이미지와 목차 표시를 제공한다. 내부 처리 이력·원시 실패 코드·판정값은 일반 화면에 표시하지 않는다. 원본 페이지 이미지는 브라우저 지연 로딩을 사용한다. 고정 페이지가 없는 문서는 본문, 근사 경계는 섹션으로 표시한다. 이미지 블록 자체에는 텍스트 목차 판정을 강제로 적용하지 않는다.

Admin 문서 처리에서 구조화 LLM 또는 System One 연결을 명시적으로 선택한다. 모델이 없으면 추출 결과를 저장하고 설정 대기한다. 설정 저장 후 대기 작업만 진행하며 완료 결과는 바꾸지 않는다. 시작한 작업은 provider config UUID를 고정하므로 설정 변경·서버 재시작 후에도 기존 설정을 사용한다.

재시도는 같은 작업의 완료된 추출과 판정 배치를 재사용한다. 명시적인 새 처리 API는 새 작업을 만들고 이전 판정 결과를 보존한다. 완료된 일반 미리보기에는 재처리 도구를 노출하지 않는다. 동일 원본·분석 프로필의 추출은 재사용한다. 프로필을 지원하지 않는 구버전 미완료 작업은 임의의 새 도구로 실행하지 않는다. 전송 진행은 Uppy, 처리 진행은 서버 Query가 소유하며 우측 하단에는 이 탭에서 업로드한 파일의 처리 상태만 표시한다. 다른 접속자는 Space의 공유 결과에서 상태를 확인한다.

고정 페이지와 슬라이드는 짧은 페이지 문맥을 한 번씩 판정한다. 원문 차례의 연속된 페이지에서 대목차와 중목차를 실제 행 순서대로 저장한다. 장의 시작 쪽수가 없으면 첫 중목차의 쪽수를 단서로 사용한다. 독립된 차례가 없는 문서는 본문에 연속해서 나타나는 명시적인 장 표제와 중간 제목을 사용한다. 제출물의 양식이나 본문 표의 행을 새 장으로 만들지 않는다. 실제 본문 표제가 차례와 유일하게 대응하면 다음 장까지 경계로 할당하고, 직접 대응이 어려우면 고정 Decision 모델이 문맥과 원문 근거를 판정한다. 원본 페이지 탭의 ‘원문 목차’에서 계층을 확인할 수 있다. 기존 완료 결과는 새 처리 작업에서만 다시 분석한다.

## Space 사용자 미리보기

Space 자료 제목을 선택하면 미리보기를 연다. 템플릿은 PPT Master에서 보존한 편집 구조와 별도로 생성한 PNG 장표를 크게 표시하며, 하단 썸네일과 이전·다음 버튼으로 이동한다. 원본 다운로드, 준비 중 상태, 실패 시 다시 시도를 제공한다. 구조 목록·판정 결과·체크포인트·분석 번들은 사용자 화면에 표시하지 않는다.

레퍼런스는 내용 검색과 원본 페이지 보기를 제공한다. 목차는 콘텐츠 구분으로만 표시하며 내부 판정 대기·신뢰도·모델 설정을 노출하지 않는다. 업로드 작업 패널은 업로드한 브라우저 탭에만 표시되고, 저장된 미리보기는 공용 자료다.

PPT Master SVG 투영을 PNG로 렌더링한 미리보기는 원본 PowerPoint와 폰트·일부 고급 효과가 다를 수 있다. 편집 가능한 원본과 구조는 별도 보존한다. 미리보기 생성이 템플릿 적용 또는 PPT 생성 기능의 완성을 의미하지 않는다.

## 본개발 Admin 처리 설정

Admin → 모델 연결 → 원하는 LLM 또는 System One 연결 → **처리 설정**에서 동시 처리 수, 대기 가능한 요청 수, 최대 대기 시간을 수정한다. 처리 중·대기 중 수를 함께 표시하며 탭이 보일 때만 주기적으로 갱신한다. 저장은 즉시 적용되고 서버 재시작 후에도 유지된다.

입력 중 다른 브라우저에서 설정을 바꾸면 입력값을 보존하고 최신 설정 검토를 요구한다. 저장 실패 시에도 입력값을 유지하며 명시적으로 다시 시도하거나 입력 취소할 수 있다. 모델 설정 변경은 이 화면의 작성 중 처리 한도 값을 덮어쓰지 않는다. LM Studio의 모델 로드 병렬 수나 외부 서버 큐를 바꾸는 기능은 아니다.

Admin 사이드 메뉴는 **일반 / LLM 연결 / Decision Model 연결** 세 개다. LLM 연결에는 생성용 Provider만, Decision Model 연결에는 구조화 출력 LLM과 전용 Decision Provider를 제공한다. 모델 선택란을 열면 현재 입력한 주소·키로 목록을 조회하며 LLM/Decision 유형을 표시한다. 저장된 연결 선택기는 기존 설정 간 전환과 추가 연결 구성을 담당한다. 판정 테스트와 공통 판정 연결 선택은 Decision Model 연결에만 둔다. 문서 처리·자료 찾기는 하나의 공통 판정 설정을 사용하며 미설정/비활성/미지원 연결이면 실행하지 않는다. 토큰 인증은 유지하며 인증 완료 배너·잠금 버튼·팀 공용 설정 문구는 표시하지 않는다.

조회는 저장 전 임시 연결 정보로 수행한다. 저장된 주소·키는 재표시하지 않으며 기존 연결에서 빈칸은 유지다. 주소·키·Provider가 달라지면 조회 결과를 무효화하고 새 조회를 요구한다. 취소·화면 이탈 시 브라우저 요청을 중단하고 늦은 결과는 반영하지 않는다. 키는 폼 수명 동안만 보관하며 Query 캐시·URL·로그에 넣지 않는다. 실제 서버 요청은 제한 시간까지 지속될 수 있다. 새 연결은 모델 선택 후 설정 저장으로 등록하고, 기존 변경은 확인창에서 대상과 변경 항목을 확인한 뒤 저장한다. 조회·탭 전환만으로 저장·추론·모델 로드·재생성을 실행하지 않는다.

LM Studio 목록은 네이티브 `/api/v1/models`의 `llm`과 `decision`을 구분하고 모델 key와 로드된 instance ID를 함께 표시한다. 서버 재시작 이후에도 로딩 설정을 사용할 때는 모델 key를 선택하며, 선택이 로드 또는 실행 가능성을 보장하지 않는다. 다른 Provider도 자체 모델 목록 API와 인증 규격을 사용한다. 서버가 기능 정보를 제공하지 않는 경우 목록만으로 Decision·Vision·Tool Calling 지원을 확정하지 않는다. 기존 변경의 버전 검사, 키 암호화, 실행 중 요청의 설정 고정, 모델별 처리 한도는 유지한다.

## 레퍼런스 재사용 자료

Space의 레퍼런스 미리보기에서 **PPT에 쓸 자료**를 연다. 장표·페이지, 그림(이미지·도형/도식·차트), 글·표로 나눠 검색하고 확인한다. PPTX는 기본으로 재사용 갤러리를 연다. 갤러리와 내용 탭은 원본 슬라이드별로 묶어 표시하고, 더 보기를 누르면 다음 항목을 같은 목록에 이어 붙인다. 다른 형식은 기존 내용 화면을 유지한다. 여러 항목을 최대 50개 선택해 **선택한 자료 보기**를 누르면 선택한 순서로 크게 확인한다. 선택은 현재 미리보기 안의 임시 상태이며 다른 브라우저에 공유되거나 PPT에 자동 삽입되지 않는다.

장표 전체는 원본 PPTX Blob과 slide part, 개별 네이티브 요소는 slide part·shape ID·미디어 part와 연결한다. 원본 이미지 바이트와 차트·도식 의존성은 원본과 PPT Master 패키지에 보존하며 미리보기 PNG로 대체하지 않는다. 글과 표의 본문은 content_block_id를 참조한다. 여러 장표 선택은 각각의 불변 ID와 순서를 유지한다. 레퍼런스 준비가 공용 템플릿 등록을 의미하지 않는다.

PDF/HWP 등은 제공 가능한 페이지 이미지, 추출 이미지, 글·표를 준비한다. Kordoc 이미지의 픽셀 크기는 보존하되 16MP/4MiB 등 기존 자원 제한을 지킨다. PPTX가 아닌 문서의 벡터 도식을 개별 편집 객체로 분리하는 기능은 없다. 도식·차트의 개별 미리보기를 만들지 못하면 포함된 원본 페이지를 표시하고 이를 카드에 안내한다. Studio의 명시적인 생성/삽입 요청은 준비된 자료를 실제 PPTX에 반영한다. PDF 벡터 복원과 임의 스타일 재구성은 후속 범위다.

기존 추출 결과는 자동 재분석하지 않는다. 재사용 자료가 없는 구버전 결과는 **재사용 자료 준비**를 명시적으로 요청해 새 추출을 만들고 기존 결과를 보존한다. 분류 모델 설정 대기 중이어도 완료된 추출 자료는 확인할 수 있다. 검색은 현재 레퍼런스의 본문·제목·페이지 문맥을 대상으로 한 키워드 검색이며 전사 의미 검색이나 자동 근거 추천을 뜻하지 않는다.

레퍼런스 추출은 Kordoc의 `dropBlankImages: true`를 사용한다. 이 옵션은 크기 하한이 아니라 흰 배경 합성 후 거의 균일한 색인 이미지(빈 판·단색 띠·옅은 배경)를 제외하는 기능이다. 작아도 형태가 있는 아이콘은 유지한다. PPT Master 경로의 개별 이미지 후보도 같은 Kordoc 구현으로 검사하며, 장표·차트·도식 전체나 원본 PPTX·패키지의 미디어 바이트는 제거하지 않는다. 처리할 수 없는 이미지 형식은 보존한다. 새 추출 프로필부터 적용하며 기존 결과를 자동 변경하지 않는다.

같은 PPTX를 템플릿과 레퍼런스로 등록해도 공통 PPT 추출과 구성 파일은 공유한다. 화면의 등록 항목·파일 버전·작업 이력은 각각 유지한다. 재사용 여부와 저장 구조는 일반 사용자에게 개발 용어로 노출하지 않으며 기존 미리보기·자료 선택 동작을 유지한다. 다운로드 시 필요한 패키지를 조립하고 과거 결과는 자동 변경하지 않는다.

## Studio 프로젝트 원본과 작성 방향

Home에서 새 프로젝트를 만들거나 카드의 제목·미리보기 영역을 선택하면 `/home/studio/{project_id}`로 이동한다. 프로젝트를 선택하기 전 Studio에서도 같은 갤러리에서 검색하거나 첫 프로젝트를 만든다. 카드는 저장된 원본·원본 확인·작성 방향·목차·근거·디자인·생성물 중 가장 뒤의 단계를 표시한다. 단계 방문 기록은 집계하지 않는다. 프로젝트를 열면 작업 화면에는 프로젝트 선택기와 연결된 원형 단계 표시를 둔다. 원본·작성 방향·목차·근거·템플릿·생성 단계가 실제 서버에 연결되어 있다. 근거와 템플릿 확인 전에는 다음 단계 진입이 제한되며, 화면 방문만으로 완료 처리하지 않는다.

문서 추가는 PDF/HWP/HWPX/DOCX/PPTX/XLSX/UTF-8 HTML을 실제 업로드한다. 업로드한 탭의 우측 하단 작업 패널에서 전송과 후속 준비 상태를 확인한다. 다른 브라우저는 같은 프로젝트 파일을 조회하지만 이 전송 패널을 공유하지 않는다. 파일 카드에서 미리보기, 원본 다운로드, 불변 파일 버전 다운로드, 교체, 논리 제거를 제공한다. 교체·제거는 기준 버전이 달라지면 충돌을 표시한다. 보관 프로젝트는 읽을 수 있으나 수정 전에 Home에서 복원해야 한다.

원본 미리보기는 원본 페이지 갤러리를 기본으로 열고 페이지별 내용 보기·검색을 제공한다. 미리보기 이미지는 고정된 프레임과 `loading=lazy`로 접근할 때 읽는다. 형식/페이지에 따라 실제 렌더 미리보기가 없으면 텍스트와 원본 다운로드를 제공하고 임의의 페이지 이미지를 만들지 않는다. 실패·취소한 문서는 다시 시도할 수 있다.

한 개 이상의 현재 원본에 추출 결과가 준비되면 **원본 확인하고 계속**으로 작성 방향에 진입한다. 분류 모델 설정 대기 중에도 이미 추출한 문서를 확인할 수 있다. 방문만으로 단계를 완료하지 않는다. 서버가 실제 파일 버전과 추출 ID의 snapshot을 비교하고 확인을 저장하며 추가·교체·제거·재추출로 집합이 바뀌면 이전 확인은 현재 완료 상태로 표시하지 않는다.

작성 방향은 선택적인 Do/Don’t 각 2,000자다. 저장할 때 새 불변 리비전을 만들며 기존 분석/생성물은 변경하지 않는다. 동시 수정 충돌에서는 입력을 보존하고 최신 버전의 내용을 확인한 다음 명시적으로 다시 저장한다. 목차 생성과 PPT 생성은 이 단계에서 실행하지 않는다.

## 과거 프로젝트 자료 찾기

Studio에서 원본이 준비되면 **과거 자료 찾기**로 이동한다. 업무 문서의 종류를 RFP로 제한하지 않으며, 발표자료·보고서·기획서·요청서 등 추출된 텍스트를 대상으로 한다. 원하는 주제를 추가하거나 원본/작성 방향만으로 검색할 수 있다. 조건을 입력하거나 화면을 방문하는 것만으로 AI를 호출하지 않으며 **관련 자료 찾기**가 실행 요청이다.

검색 범위는 다른 프로젝트의 원본이다. 보관 프로젝트, 이전 파일 버전, 형식, 등록 시기, 특정 프로젝트를 선택할 수 있고 삭제된 프로젝트/자료는 새 검색에서 제외한다. 기본 UI는 보관 프로젝트를 포함하고 최신 파일 버전을 사용한다. 프로젝트 선택 목록에는 최근 100개를 표시하지만 ‘모든 다른 프로젝트’는 전체 범위에서 후보를 찾는다. 공용 Space 문서를 대신 복사하거나 자동 등록하지 않는다.

결과는 문서/내용 탭의 뉴스형 행으로 제공한다. 썸네일, 원본 파일명·버전·페이지, 일치 발췌, 관계 표시와 실제 소속 프로젝트를 함께 보여준다. 같은 추출 내용은 한 후보로 묶고 프로젝트 수와 등록/버전 수를 구분한다. 소속 목록은 페이지 단위로 모두 조회할 수 있다. 내용 결과의 미리보기는 해당 과거 버전의 페이지로 열며 원래 프로젝트로 이동하는 링크도 제공한다.

관계 표시는 ‘같은 업무 맥락’, ‘뒷받침 자료’, ‘재사용할 접근 방식’, ‘차이 확인 필요’, ‘직접 확인 필요’다. 비관련 판정은 일반 결과에서 제외하되, 사용자가 이미 선택한 자료를 자동 제거하지 않는다. 비교 전에도 원문을 확인해 직접 참고 자료로 선택할 수 있으며 이는 AI의 확인 완료를 의미하지 않는다. 표시하지 않은 모델 확률을 임의의 일치도 점수로 바꾸지 않는다.

진행 중에는 실제 완료 후보 수를 표시하고 취소·실패 후 이어서 찾기를 지원한다. 완료 판정은 재사용하며 실패를 ‘관련 없음’으로 처리하지 않는다. 원본 또는 가이드가 바뀌면 기존 검색을 오래된 결과로 표시하고 새 선택 전에 다시 검색해야 한다. 선택한 출처 버전은 교체 후에도 유지한다. 원래 프로젝트에서 제거된 자료는 선택 이력을 보존하고 원본 열기를 비활성화한다.

Admin → **자료 찾기**에서 해당 작업의 AI를 별도로 지정한다. 모델 설정을 기다리던 검색은 설정 후 이어가지만 완료된 검색은 자동 재실행하지 않는다. 검색은 추출된 텍스트의 제한된 후보와 일부 문맥을 비교하며, 이미지·차트에 대한 Vision 검색, 전체 문서의 전수 비교, 선택 자료의 PPT 삽입은 현재 범위가 아니다.

## Studio 목차·내용 구성

1. 프로젝트 원본을 올리고 추출된 내용을 확인한다. 명시적으로 원본 확인을 완료한다.
2. 선택적인 Do/Don’t를 저장한다. 저장하지 않은 가이드로 다음 단계에 진입하지 않는다.
3. 목차·내용의 AI로 구성을 열어 목차를 만들거나 직접 작성한다. 가로 목차에서 하나를 선택하면 사용할 내용과 원문 근거를 비교한다. 목차 편집은 별도 대화상자에서, 원문 추가는 내용 담기에서 수행한다. 대목차/중목차는 최대 24개, 두 단계다. 추가·삭제·제목/설명 수정·상하 이동·상위 목차 변경을 지원한다.
4. 목차별 원문 내용을 확인한다. 전체 또는 선택 목차에 자동 연결을 실행할 수 있으며, 원문 검색/선택으로 연결을 추가·제거할 수 있다. 같은 정본 블록을 여러 목차에 연결할 수 있다.
5. 목차·연결을 저장하고 모든 마지막 목차에 최소 하나의 원문이 연결되면 명시적으로 확정한다. 방문·저장·AI 완료만으로 확정하지 않는다.
6. 이전 버전을 읽기 전용으로 조회한다. 원본·가이드 변경은 기존 결과를 수정하거나 재생성하지 않으며 현재 구성은 재검토 상태가 된다. 기존 목차를 유지하고 연결을 다시 검토하는 명시적 작업을 제공한다.

생성은 원본/가이드/모델 설정과 기준 목차 버전을 고정한다. 진행 중 수동 저장이나 입력 변경이 발생하면 오래된 AI 결과는 현재 목차에 적용하지 않는다. 이미 검증된 작업 결과는 보존되고 실패한 배치부터 명시적으로 재시도한다. 모델 없이 수동 작성·연결·확정도 가능하다.

자동 목차는 원문 최대 2,000개 블록 중 문서별 순서를 분산한 최대 48개 발췌를 사용한다. 전체 자동 연결은 최대 2,000개를 8개 단위로 처리한다. 긴 본문은 발췌하며 선택된 문단/이미지의 원문 전체는 미리보기에서 확인한다. 텍스트 기반 추천이며 이미지 의미 이해나 모든 실무 문서에 대한 내용 정확도 보장은 아니다. PPT 생성은 다음 단계다.

## 추가 근거 탐색

Studio의 과거 자료 찾기는 정보 부족·조건 차이 판정에 앞뒤 문맥과 다른 자료를 공급해 재검토한다. 필요하면 추가 검색으로 후보를 가져오며 사용자가 정한 프로젝트·형식·기간·보관·버전 조건을 유지한다. 원본·가이드·설정 저장만으로 기존 검색을 다시 실행하지 않는다.

Admin 자료 찾기에서 판정용 Decision/LLM과 검색어 보완용 LLM을 각각 선택한다. 보완 LLM 미선택 시 읽은 원문의 단어로 찾는다. 설정한 LLM의 실패를 다른 모델이나 규칙으로 몰래 대체하지 않는다. 진행 중 검색은 시작 시 설정을 유지한다.

결과의 **원문 문맥**에서 해당 발췌와 함께 비교한 자료를 확인한다. **원문 보기**는 정확한 파일 버전과 페이지를 연다. 생략된 내용은 표시하며 전체 보기로 구분한다. 정보 부족·조건 차이는 사용자가 확인할 상태로 남는다. 텍스트/표 문맥 탐색이며 이미지 의미 검증이나 PPT 삽입 완료를 뜻하지 않는다.

## 근거 단계에서 추가 검색

상단 프로젝트 영역의 과거 자료 찾기 버튼은 제공하지 않는다. Studio 네 번째 근거 단계에서 선택한 근거를 검토하고 추가 검색을 실행한다. 기존 `step=related` 링크는 실행 ID를 유지하며 `step=evidence`로 연결된다. 원본이 준비된 기존 링크는 계속 사용할 수 있고 미저장 목차에서는 단계 버튼을 통한 앞으로 이동을 막는다. 근거 확정과 템플릿 단계의 완료 처리까지 구현한 것은 아니다.

Space 검색 홈 우측 상단에서 바로 자료를 올린다. 전체 탭에서는 레퍼런스 또는 템플릿을 선택하고, 개별 탭에서는 해당 종류의 등록 창이 바로 열린다. 검색어가 없으면 같은 화면에 자료 목록을 표시하며 카드 메뉴에서 정보 수정·파일 버전·보관을 처리한다. 전역 검색도 같은 Space 검색 결과와 문서 상세를 사용한다. 공용 자료 검색 범위와 프로젝트별 추가 검색 범위는 서로 바뀌지 않는다.

## 실제 PPT 생성과 결과 확인

목차를 확정한 뒤 근거 단계에서 현재 선택을 확인한다. 추가 근거를 선택하지 않았다면 현재 프로젝트 원본만으로 작성한다. 추가 근거는 최대 40개이며, 확인 이후 원본·가이드·목차·근거 선택이 달라지면 재확인한다. 템플릿 단계에서는 기본 디자인 또는 준비 완료된 Space 템플릿을 선택한다. 미리보기와 선택은 별개이며 확정 시 정확한 처리 작업/파일 버전을 고정한다.

생성 단계 본문에서 **생성할 목차**, 제목, 선택적 추가 요청을 바로 입력한다. 별도의 ‘PPT 생성 설정’ 버튼이나 접기 영역은 없다. 데스크톱에서는 목차와 작성 입력을 나란히, 모바일에서는 세로로 배치한다. 생성된 자료가 있으면 현재 편집 캔버스를 먼저 보여주고 추가 생성 폼을 그 아래에 둔다. AI/직접 작성 탭은 제공하지 않는다. 목차 행의 회색 연필은 제목·순서 편집, 대목차의 ＋는 중목차 추가를 연다. 새 중목차는 해당 상위 목차·기존 중목차의 원문 ID를 함께 참고하며 새로운 모델 판정을 의미하지 않는다. 저장은 새 목차 리비전과 현재 근거·템플릿에 대한 준비 상태를 갱신한다. 선택 범위가 이전 리비전에 묶여 있으면 다시 선택하도록 안내한다. 새 버전 명령은 제목 입력란으로 초점을 이동하고 생성 요청 후에는 결과 제목으로 이동한다. 기본은 전체 선택이며 대목차를 선택하면 하위 중목차 전체가 포함되고 중목차를 개별 선택할 수도 있다. 일부만 선택한 대목차와 전체 선택에는 부분 선택 표시를 제공한다. 선택한 마지막 목차마다 한 장씩 최대 24장을 원래 목차 순서로 작성한다. 선택하지 않은 목차는 이번 파일에 포함하지 않는다. 기존 생성 API의 명시적 자료 입력을 사용하는 경우 원본 장표는 별도로 추가한다. 빈 선택은 생성하지 않는다. 각 장은 연결된 원문 최대 12곳(각 700 UTF-8 바이트)과 선택한 추가 근거의 대표 발췌(각 200바이트)를 참고한다. 전체 문서를 모델에 모두 전달한다고 표시하지 않는다. 목차 제목·원문과 Do/Don’t를 고정하고 슬라이드별 구조화 응답과 canonical 근거 ID를 검증한다.

생성 화면에는 AI 선택란을 제공하지 않는다. 서버가 Admin에 등록된 활성 LLM 중 최초 등록 순서(동률이면 연결 ID)로 하나를 선택하고 접수 시 설정 버전을 고정한다. Decision 연결은 제외한다. 새 버전은 기존 발표자료의 연결을 계속 사용하며 해당 연결을 쓸 수 없으면 다른 모델로 바꾸지 않고 관리자 확인을 안내한다. 연결이 없어도 목차와 입력을 유지하며, 설정 이후 같은 화면에서 다시 요청할 수 있다. 설정 가능한 작업별 모델 라우팅은 별도 미구현 범위다.

생성 범위 선택은 조회와 로컬 초안만 변경하며 모델 호출이나 기존 결과의 재생성을 일으키지 않는다. 확정 목차가 달라지면 선택 범위를 다시 확인해야 한다. 새 버전 생성에도 화면에서 선택한 범위가 적용되고 이전 파일은 유지된다. 선택하지 않은 장표를 새 버전에 자동 병합하는 부분 교체 기능과는 구분한다.

완료한 내용 초안은 생성 중에도 읽을 수 있다. 파일 렌더링과 Kordoc 재추출 검사를 통과하면 실제 장표 PNG와 PPTX 다운로드를 제공한다. 슬라이드 내용·메모·연결 원문은 펼쳐 볼 수 있으며, 근거에서 정확한 원본 버전과 페이지 미리보기를 연다. 사용자 화면에는 모델 응답·SQL·저장 경로·내부 오류 코드를 노출하지 않는다.

기본 디자인은 PPT Master의 SVG→네이티브 DrawingML 출력을 사용한다. 업로드 템플릿은 python-pptx로 원본 마스터/테마/레이아웃을 유지하고 제목·본문 슬롯에 내용을 채운다. 원본의 모든 샘플 장표를 복제하는 기능은 아니며, 제목/본문 슬롯이 없거나 본문이 들어가지 않는 템플릿은 조용히 다른 디자인으로 바꾸지 않고 실패한다. 장표 미리보기는 PPT Master의 최종 파일 재수입 결과이며 PowerPoint 화면과 고급 효과·폰트가 다를 수 있다.

실패·취소 시 완료한 슬라이드 초안은 유지된다. ‘이어서 만들기’는 완료되지 않은 모델 요청부터 실행하고 필요한 파일 렌더링을 다시 수행한다. ‘이 발표자료 새 버전 만들기’는 별도 명시적 생성이며 이전 파일을 보존한다. 공유 상태가 바뀌면 충돌을 표시하고 자동으로 덮어쓰지 않는다. 최근 생성 작업 50개를 조회한다.

웹 캔버스의 직접 객체 편집, 시각 모델의 자동 품질 평가/수정, 목표 장수에 따른 자유 분량 조정은 후속 범위다. 현재 결과는 PowerPoint에서 텍스트·도형을 편집할 수 있다.

## Admin 일반 설정

모델 설정의 **저장 전 연결 진단**은 입력 중인 주소·인증·모델·토큰 설정으로 짧은 실제 요청을 보낸다. LM Studio에서 로딩 파라미터가 지정되면 일치하는 인스턴스를 재사용하거나 먼저 준비한다. Thinking 기본값은 옵션 생략이다. 켜기와 effort 변경은 켜기 단독과 네 단계(low/medium/high/xhigh)를 각각 시험한다. 명시적 모델 정보가 없으면 알 수 없는 effort도 수락하는 서버인지 확인한다. 인증·네트워크 오류는 미지원으로 판정하지 않는다. 켜기 단독은 통과하고 지정한 effort만 거절된 경우에는 강도 없이 저장한다. 단계 지정이 필수인 모델에서 사용자가 effort를 비우면 진단이 통과한 단계 중 medium, low, high, xhigh 순으로 적용할 값을 표시한다. 전용 Decision 요청에는 Thinking 옵션을 넣지 않는다. LLM 판정은 같은 연결의 작성 설정과 독립적으로 끄기를 요청하고, 실제 추론 흔적이 관찰되거나 서버가 끄기를 거부하면 실패로 표시한다.

처음 Admin에 들어갈 때 서버 실행 터미널의 임의 토큰을 입력한다. Admin → 일반 설정에서 새 토큰과 확인값을 입력하고 변경 확인을 거친다. 적용 후 현재 화면과 다른 접속자의 기존 Admin 인증이 더 이상 유효하지 않으며 새 토큰으로 다시 들어간다. 새 토큰은 현재 서버 실행 동안만 유효하다. **서버를 재시작하면 새 임의 CLI 토큰으로 같은 초기 진입 절차를 다시 시작한다.** 프로젝트·Studio·Space와 진행 중인 문서/PPT 작업은 영향을 받지 않는다.

생성 결과는 좌측 슬라이드 목록·중앙 미리보기·우측 AI 대화/내용·메모/참고 자료 패널에서 검토한다. 양쪽 패널을 따로 접을 수 있고 이전/다음 장표와 미리보기 확대·축소·맞춤을 제공한다. 이 동작은 PPT 내용 수정이 아니다. Studio 단계 표시는 스크롤 중에도 유지된다.

현재 장표를 대화로 수정하려면 **AI와 대화**에서 AI와 수정 범위를 선택한다. 요청 후 수정 전후를 확인하고 **수정안 적용**을 눌러 새 PPTX 버전을 만든다. 제목만을 선택하면 본문·메모·근거와 다른 장표는 서버에서 보존한다. 수정안을 버리거나 실행 중 요청을 취소할 수 있으며 이전 버전은 계속 다운로드할 수 있다. 이미지·차트·도형·텍스트 상자와 배치도 같은 수정안 검토/적용 흐름을 사용한다. 좌측 장표에서 여러 장을 고르면 같은 요청을 일괄 적용한다. 객체 탭의 이미지 등록·차트 데이터 입력은 요청 초안을 만들며 사용자가 전송하고 적용하기 전에는 장표를 바꾸지 않는다.

## Space·Studio 자료 준비와 재개

Space 레퍼런스와 Studio 원본은 **문서 읽기 → 내용 정리 → 검색·작성 준비**로 표시한다. 템플릿은 **템플릿 미리보기 준비 → 사용 준비**로 구분하며 문서 분류를 호출하지 않는다. 문서 읽기에는 형식별 추출과 필요한 OCR이 포함된다. 기술적 실행 단계와 Studio의 여섯 검토 단계는 별개이며 파일 준비가 사용자의 검토를 대신 완료하지 않는다.

업로드한 탭은 우측 하단 작업 패널에서 현재 준비 상태를 보고 취소하거나 실패·취소된 작업을 다시 시도한다. 패널을 닫아도 작업을 취소하지 않는다. 다른 접속자는 전송 패널을 공유하지 않지만 자료 미리보기에서 같은 영속 준비 상태와 결과를 확인한다. 내용 정리의 실제 처리 수만 진행률로 표시하고 추출 소요시간의 백분율을 추측하지 않는다. ‘완료 항목 정리’는 해당 파일 버전의 자료 준비가 성공한 항목만 지운다. 마지막 항목을 정리하면 빈 패널이 남고, 실패·설정 대기·취소 항목은 개별적으로 숨길 수 있다. 읽기 실패의 작업 상세와 서버 터미널에 같은 작업 ID와 오류 코드가 표시된다.

모델 미설정 시 원본과 추출 결과를 보존하고 설정 대기로 표시한다. 재시작·재시도는 완료한 추출과 분류 배치를 재사용하고 실행 당시 모델 설정을 유지한다. 프로젝트 원본은 Space에 자동 등록하지 않는다. 취소·재시도는 저장된 버전과 멱등 요청을 검사하고 충돌 시 최신 상태를 다시 확인한다. OCR 페이지별 독립 재개와 LibreOffice 기반 Office PDF 정규화는 이 구현 범위가 아니다.

## 목차·내용 작업의 진행과 이어하기

Studio는 목차 자동 생성에 **목차 구성 → 결과 저장**, 자동 내용 연결에 **내용 연결 → 결과 저장**을 표시한다. AI 설정 영역을 접어도 진행·실패·취소·이어하기는 보이며 완료된 단계도 확인할 수 있다. 실제 완료한 처리 묶음 수를 표시하고 전체 소요시간의 백분율은 추측하지 않는다. 처리 묶음이 끝났어도 결과 저장이 완료되기 전에는 성공으로 표시하지 않는다. ‘완료 항목 정리’는 해당 파일 버전의 자료 준비가 성공한 항목만 지운다. 마지막 항목을 정리하면 빈 패널이 남고, 실패·설정 대기·취소 항목은 개별적으로 숨길 수 있다. 읽기 실패의 작업 상세와 서버 터미널에 같은 작업 ID와 오류 코드가 표시된다.

취소·실패·재시작 후에는 완료한 묶음을 재사용하고 미완료 묶음만 모델에 요청한다. 최종 저장만 실패한 경우 저장부터 다시 시도하며 기존 목차를 보존한다. 작업 도중 모델 연결 기본값이 바뀌어도 접수한 설정을 유지한다. 원본·작성 방향·목차가 변경돼 적용 조건이 맞지 않으면 기존 편집을 덮어쓰지 않고 최신 내용으로 다시 시작하도록 안내한다. 자동 구성 완료는 사용자의 목차·내용 확정을 대신하지 않는다. 프로젝트 원본은 Space 검색에 자동 등록되지 않는다.

## 레퍼런스를 포함한 제작 흐름

일반 생성 폼에는 **레퍼런스 넣기**를 제공하지 않는다. 앞서 확정한 문서 근거는 생성에 이어받는다. 명시적 자료 삽입을 받는 기존 생성 API는 job/material ID를 고정하며, 편집기의 참고 자료 탭은 완성된 장표에 자료를 추가할 수 있다. 장표·페이지는 덱 마지막에 추가하고 그림·차트·글은 첫 장표에 넣는다. 초안 본문과 자료의 영역을 나누며 실제 PPTX 렌더링까지 완료해야 성공이다. 선택을 바꾸는 것만으로 기존 출력은 재생성하지 않는다. 최초 생성 중 보강 전 모델 초안도 별도 Blob 참조로 보존하고, 중단 후 자료 적용을 반복하지 않는다.

완료 후 참고 자료 탭에서는 현재 장표에 추가하거나 원본을 다시 열고, 선택한 객체를 대화로 수정할 수 있다. 검색의 제한된 추가 확인·분류 캐시와 대화의 장표별 수정안 체크포인트는 재시작 후 재사용한다. 미리보기 완료는 적용 승인을 대신하지 않는다. 최종 다운로드는 고정한 출처와 네이티브 객체를 포함한 실제 PPTX다.
