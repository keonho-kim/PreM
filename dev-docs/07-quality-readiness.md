# 품질·보안·운영 준비도

검사 명령의 존재, 합성 테스트의 통과, 실제 외부 모델·업무 문서의 수용 결과를 구분한다. 화면 캡처만으로 저장·복구·모델 품질을 보장하지 않는다.

## 공통 검증 게이트

`pnpm check:core`는 개발 품질을 검증한다. 게시 조건은 [릴리스 운영 절차](06-development-operations.md#날짜-버전-릴리스)를 따른다. 버전·디자인 토큰·런타임·오프라인 PDF/PPT·백업 단위 검사, 포맷·구조·lint·Knip, 전체 Rust 단위/통합/doc 테스트·Clippy, 전체 React 테스트·npm advisory 검사를 포함한다.

`pnpm check`는 위 게이트에 설치된 Rust 개발 도구 확인과 cargo-deny/machete 정책 검사를 추가한다. `pnpm test:e2e`는 실제 서버·브라우저에서 모든 등록된 여정을 실행하고 실패 후에도 다음 여정을 검사한다. `tests/.artifacts/e2e/report.json`과 각 로그가 해당 실행의 결과다. 특정 여정만 실행하려면 이름을 인자로 전달한다. CI는 고정 Puppeteer가 지정한 Chrome for Testing 버전을 설치한다. 반응형 검사는 viewport 변경 후 폰트·ResizeObserver·프레임 갱신을 기다리고, 클릭은 Locator의 표시·활성화·위치 안정화 검사를 사용한다. 실패한 CI는 입력값을 가린 종료 화면·배치 정보와 여정 로그를 7일간 보관한다.

| 작성      | 목차·매핑, 근거·템플릿 고정, PPTX 생성·검토·재시작·부분 재사용                      |

## 문서 준비와 파싱 평가

문서 준비는 공통 판정 모델이 설정되어야 시작한다. 모델 미설정 대기는 실제 gate 테스트에서 검사하고, 파싱·검색·뷰어 테스트는 명시적인 로컬 분류 fixture를 설정한다. `pnpm audit:parsing`은 고정된 공개/합성 문서와 사람이 작성한 기대값을 비교하며 외부 모델을 사용하지 않는다. 이 결과는 실제 업무 문서 전체의 정확도 수치가 아니다.

`kordoc-runtime.test.mjs`는 실제 문서 어댑터를 오프라인 설정·Node 파일 권한·개발 실행기가 없는 PATH로 호출한다. 한국어 텍스트 PDF와 텍스트/스캔 혼합 PDF의 원문·페이지 미리보기를 검사하며 OCR 쓰기는 테스트 전용 캐시에만 허용한다.

## 모델 요청 문맥 검증

`inference/context.rs`는 한국어 전체 근거 보존, JSON escape/Unicode를 포함한 실제 바이트 한도, 앞·뒤 발췌 범위와 초과 지시문 거부를 검사한다. `prompt_context.rs`는 실제 HTTP 요청에 마지막 조건과 제공량이 도착하는지 검증한다. 문맥 예산은 모델별 토크나이저 자동 산정이나 전체 문서 의미 보존을 보장하지 않는다.

## 장표별 품질과 부분 렌더링 검증

제목·본문·근거·차트 값·이미지 비율·배치 경계를 검사하고, 최초 생성의 제한된 글자 크기 보정 후에도 해결되지 않은 장표는 완료하지 않는다. 기존 검증 결과와 렌더를 재사용하는 동작은 발표·편집 통합 테스트가 담당한다. 글자 폭/높이는 보수적 추정이며 모든 폰트의 실제 조판·시각적 품질·근거의 의미 정확성을 증명하지 않는다.

## 운영 수용의 남은 범위

- 실제 클라우드 계정 및 사용 모델별 한국어 작성·판정 품질은 별도 실모델 평가가 필요하다. 합성 fixture는 계약 검증이다.
- 임의 PowerPoint 객체의 완전한 편집, 애니메이션·그룹화·복잡한 원본 내부 편집과 슬라이드 목록 포인터 정렬은 전체 지원을 주장하지 않는다.
- SSE, 범용 병렬 DAG/동적 분기, 범용 사용자 승인 노드는 후속 범위다.
- 회사 네트워크·HTTPS·볼륨·백업 주기는 배포 환경에서 구성한다. 백업 도구는 명시적 오프라인 스냅샷이며 온라인/주기적 백업 서비스가 아니다.
- macOS Developer ID 서명·공증은 적용하지 않았다. Linux 최소 OS와 외부 추론 서비스 조건은 릴리스 README를 따른다.

실제 동작의 출처는 [업무 흐름](02-product-workflows.md), [편집기](03-editor.md), [데이터 계약](04-data-api.md), [운영 절차](06-development-operations.md)다.

## 파싱 감사의 확인된 미통과 항목

고정 corpus의 `korean-columns.pdf`는 두 단 본문을 Kordoc이 2열 표로 분류하여 기대한 열 우선 읽기 순서와 다르다. `multi-sheet.xlsx`는 표시된 계산값은 추출되지만 수식 `SUM(B3:B4)`가 Kordoc 결과에 별도 메타데이터로 제공되지 않는다. 현재 7문서 중 5문서가 모든 기대값을 충족하고 27개 검사 중 2개는 미통과다. 기대값을 완화하거나 성공 baseline으로 바꾸지 않으며 `pnpm audit:parsing`은 이 두 품질 문제를 실패로 보고한다. 이 감사는 배포 기본 기능/복구 게이트와 별도의 품질 보고이며 전체 문서 충실도 완료를 주장하지 않는다.
