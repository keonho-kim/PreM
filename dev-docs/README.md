# PuPuTyX 개발 문서

PuPuTyX는 같은 회사 안에서 우리 팀이 사용하는 공용 도구로, 업무 문서를 분석하고 근거를 연결해 편집 가능한 프레젠테이션을 만드는 플랫폼이다. 이 문서 모음은 **현재 저장소에 구현된 코드와 동작**을 설명한다. 제품 요구사항과 목표 아키텍처는 [blueprint](../blueprint/README.md)가 담당한다.

현재 제품은 로그인 없이 공유 프로젝트와 Space 자료를 관리하고, Admin에서 LLM/Decision 연결을 설정한다. Studio는 원본 등록·분석, 선택적 Do/Don’t, 목차 생성·편집·내용 연결, 근거 검색·확정, 템플릿 선택, **편집 가능한 PPTX 생성·미리보기·다운로드**를 제공한다. 생성 실패·취소 후 완료한 슬라이드 초안부터 이어갈 수 있고, 같은 발표자료의 새 버전을 명시적으로 만들 수 있다. 실제 AI 대화로 현재 장표의 제목·본문·메모를 수정하고 검토 후 새 PPTX 버전으로 적용한다. 웹 캔버스 객체 편집은 아직 목업이며 세부 객체 조작은 내려받은 PPTX에서 수행한다. 운영 전 필요한 조건은 [품질·보안·운영 준비도](07-quality-readiness.md)에 정의한다.

## 구현 범위

프로젝트 기본 기능은 실제 제품이며, 이름과 마감일로 빈 프로젝트를 만든다. 프로젝트를 만들거나 열면 Studio 원본 등록 단계로 이동한다. 모든 사용자는 같은 목록을 보고 변경하며 인증·개인별 소유권 필터는 없다.

Space 레퍼런스는 UTF-8 HTML/HTM 원본도 등록·버전 관리·다운로드할 수 있다. HTML을 앱 내부에서 렌더링하거나 스크립트·외부 리소스를 실행하지 않으며, 본문을 안전한 텍스트 블록으로 추출한다. 원본 HTML 화면을 실행·렌더링하지 않는다.

## 문서의 적용 범위

- 실제 동작의 근거는 각 문서가 연결하는 소스와 테스트다. 테스트 명령의 존재와 해당 환경에서의 통과 여부는 구분한다.
- `dev-docs/`는 구현 설명을, `blueprint/`는 제품·기술 요구사항을 담당한다. 계획된 테이블이나 API를 구현된 계약으로 취급하지 않는다.
- 목업 상태는 새로고침으로 초기화된다. 실제 사용자 자료 보관, 복구, 공동 작업의 근거로 사용하지 않는다.
- 테스트 캡처는 [Folio 화면](../mock/captures/folio/README.md)에서 확인할 수 있다. 캡처는 특정 화면 상태를 보여주며 기능 전체의 검증을 대체하지 않는다.

프로젝트의 상세 HTTP 계약은 [데이터·API](04-data-api.md), 실제 사용자 흐름은 [업무 흐름](02-product-workflows.md)을 따른다.

작업 진행/완료는 우측 하단 패널에서 확인하며, 짧은 알림은 그 위에 토스트로 표시한다. 상단 종 아이콘과 생성 FAB는 없고 Home 상단에서 프로젝트를 만든다. 목업도 동일한 배치를 사용하지만 작업 처리는 시뮬레이션이다.

Admin은 전용 사이드 메뉴(모델 연결·문서 처리·시스템 상태)와 항상 표시되는 LLM / Decision 탭을 제공한다. Provider별 주소·키로 저장 전 모델 목록을 조회하고 선택하며 별도 추가 버튼이나 모델 ID 직접 입력은 없다. 등록 후 연결 설정·처리 설정·연결 테스트·판정 테스트·요청 이력을 관리한다. URL로 선택을 복원하되 Admin 진입에는 서버 시작 때 CLI에 표시된 토큰이 필요하다. 일반 프로젝트 이용에는 로그인이 없다.

Provider 선택지·기본값·지원 기능은 서버 카탈로그가 소유한다. 일반 추론 실행, 연결 진단, 네이티브 프로토콜, 시작 복구 쓰기의 책임은 [아키텍처 문서](01-architecture.md#추론카탈로그시작-복구의-책임)에 구분되어 있다.

Decision은 독립 내부 모듈이다. 9개 native 판정 연결과 LLM bridge의 텍스트 choice 평가를 Admin에서 실행할 수 있다. Space의 Worker·원본 블록 판정·영속 결과 저장에 연결되어 있다. 실제 클라우드 계정 검증은 미완료다.

## 일반 사무직 사용자 경험

주 사용자층은 일반 사무직군이다. 개발·AI 운영 지식을 요구하지 않는 업무 표현과 미리보기 중심의 경험을 기준으로 한다. 목업은 전체 화면에 이 정책을 적용하며, 제품 React 화면의 전면 문구 감사·전환은 별도 검증 범위다.

레퍼런스는 장표·그림·글 단위 재사용 자료를 준비한다. PPTX 원본과 네이티브 패키지, canonical 본문을 버전별로 연결하며 Space에서 검색·여러 자료 선택·확대 검토가 가능하다. 이 선택 화면은 실제 PPT 삽입이나 생성 기능의 완성을 뜻하지 않는다. 자세한 범위는 [제품 흐름](02-product-workflows.md#레퍼런스-재사용-자료)을 따른다.

PPT의 공통 추출은 원본/분석 프로필별로 공유하며 이미지·구조 파일·미리보기는 개별 Blob으로 저장한다. 다운로드 ZIP은 요청 시 조립한다. 기존 결과를 보존하고, 서버 시작 때만 7일 이상 미참조인 Blob을 백업 참조까지 검사해 정리한다. [저장 수명과 호환 계약](04-data-api.md#공통-ppt-패키지와-저장-수명)에 적용 범위와 제한을 정의한다.

Studio의 **과거 자료 찾기**는 현재 원본·작성 방향과 다른 프로젝트의 문서를 비교한다. 파일/내용별 결과, 실제 프로젝트 소속, 과거 버전 미리보기와 참고 자료 선택을 제공한다. 관계 판정은 Admin → 자료 찾기에서 지정한 Decision 또는 구조화 LLM 연결을 사용한다. 네이티브 Decision은 후보별 입력을 병렬 처리하고 LLM은 묶음 처리하며, 완료된 동일 입력 판정은 재사용한다. Space 공용 등록이나 PPT 생성은 이 검색의 부수 효과가 아니다.

Markdown은 Space 레퍼런스와 Studio 원본에서 `.md`/`.markdown`으로 업로드한다. UTF-8, 최대 2 MiB이며 Comrak 기반 Rust 어댑터가 구조화 블록과 원문 위치를 저장한다. 화면에서는 안전한 텍스트로 조회·검색하고 원본은 다운로드할 수 있다. 링크·이미지 URL을 가져오거나 Markdown의 HTML을 실행하지 않는다. [상세 계약](04-data-api.md#markdown-원본추출-계약).

Space 통합 검색은 상단 검색창과 `/home/space`에서 제공한다. 공용 레퍼런스의 파일 정보·본문과 템플릿의 이름·태그를 뉴스형 결과로 찾고, 정확한 버전의 문서 페이지로 이동한다. 프로젝트 원본은 이 검색에서 제외하며 Studio의 관계 검색과 구분한다.

Studio의 목차·내용 단계는 저장된 원본 확인과 작성 방향을 기준으로 동작한다. AI 생성은 사용자가 명시적으로 실행하며, 연결하지 않은 목차는 원문 내용을 추가한 뒤 확정한다. 원본·가이드 변경 시 기존 목차를 보존하고 재검토 상태로 표시한다. 모델 없이 직접 목차를 작성하고 내용을 연결할 수도 있다.

Studio 자료 찾기는 주변 문맥 재검토와 추가 검색을 지원한다. Admin에서 판정 모델과 선택적 검색 계획 LLM을 설정하고 결과의 원문 문맥에서 고정된 출처를 확인한다. 일반 Space 통합 검색의 범위는 유지한다. 상세 한도는 [검색 작업 공간 계약](04-data-api.md#v18-검색-작업-공간)을 따른다.
