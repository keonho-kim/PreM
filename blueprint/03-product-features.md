# 사용자 기능

PuPuTyX 통합 제품·기술 설계서 v2.0. 원문 **4장**을 수록한다. [문서 색인](README.md)

기능의 화면 구성은 [UI 설계](07-ui-design.md), 실행 조건은 [Workflow](04-workflow-engine.md), 저장 관계는 [데이터 모델](05-data-storage.md)을 따른다.

## 4.1 프로젝트 관리

### 프로젝트 생성

| 입력 요소 | 필수 여부 |
| --- | --- |
| 프로젝트 이름 | 필수 |
| 원본 문서 1개 이상 | 필수 |
| 추가 참고 문서 | 추가 입력 |
| PPTX 템플릿 | 선택 |
| 프로젝트 가이드 | 선택 |

생성 직후 프로젝트 ID와 독립 Workspace를 생성한다. 초기 문서 변환 및 분석은 백그라운드에서 실행한다.

### 관리 기능

- 프로젝트 목록, 검색 및 상태별 필터
- 프로젝트 생성·이름 변경·복제
- 프로젝트 보관·복원
- 프로젝트 삭제 및 보존기간 관리
- 문서 추가·교체
- 생성된 PPT 목록
- 프로젝트 활동 및 Workflow 이력
- 최근 생성물과 적용 가이드 버전 표시

로그인이 없으므로 모든 접속자는 동일한 프로젝트 목록을 조회한다. 프로젝트별 폴더와 DB 외래 키로 데이터 혼합을 방지하지만 사용자별 접근 제어는 제공하지 않는다.

## 4.2 문서 관리

지원 입력 형식은 **PDF, HWP, HWPX, DOCX, PPTX, XLSX**다.

### 문서 기능

- 원본 파일 보존 및 다운로드
- 파일 교체 및 버전 이력
- PDF 자동 변환
- 페이지별 미리보기
- 텍스트·표·이미지 추출
- 필요한 페이지의 Kordoc OCR
- 추출 실패 페이지 표시
- 원본과 추출 결과 비교
- 페이지 단위 재추출 요청

원본은 항상 수정 불가능한 파일 버전으로 유지한다. 교체는 새 파일 등록으로 처리한다.

변환 실패 시에도 원본을 그대로 보존하고 실패 원인과 재시도 기능을 제공한다. 원본과 변환본, 추출 결과의 관계를 추적한다.

## 4.3 프로젝트 가이드

프로젝트 전체의 분석 및 콘텐츠 작성 방향을 정의한다.

### 입력 필드

| 필드 | 설명 |
| --- | --- |
| 목표 | 프로젝트의 최종 목적 |
| 대상 독자 | 결과물을 읽거나 보는 사람 |
| 핵심 강조사항 | 우선적으로 다뤄야 하는 주제 |
| 필수 포함사항 | 반드시 포함할 콘텐츠 |
| 제외·주의사항 | 부적절하거나 근거 없는 주장 방지 |
| 콘텐츠 구성 방향 | 논리 전개와 스토리라인 |
| 레퍼런스 선호 | 우선 탐색할 근거·자료 유형 |
| 시각화 지침 | 차트·도식·이미지 사용 방향 |
| 자유 지침 | 추가적인 자연어 요구사항 |

가이드는 변경할 때마다 새로운 불변 리비전을 생성한다.

### 변경 적용 정책

- 가이드 저장은 DB 변경만 수행한다.
- 기존 목차와 콘텐츠 매핑은 수정하지 않는다.
- 기존 레퍼런스·템플릿 탐색 결과는 유지한다.
- 기존 PPT와 슬라이드도 변경하지 않는다.
- 새로운 Workflow 실행 시 최신 가이드를 기본 적용한다.
- 기존 결과에 적용하려면 사용자가 재실행 또는 재생성을 명시적으로 요청해야 한다.
- 이미 실행 중인 Workflow는 시작할 때 선택한 가이드 버전을 계속 사용한다.

## 4.4 목차 및 콘텐츠 매핑

### 목차 기능

- 원본 문서 목차 추출
- LLM 기반 새로운 목차 생성
- 대목차·중목차 계층 관리
- 목차 추가·삭제·이동·순서 변경
- 목차별 설명 수정
- 목차 버전 관리
- 원본 목차와 생성 목차 비교

### 콘텐츠 매핑 기능

- 목차별 문서 블록 자동 할당
- 동일 블록의 다중 목차 할당 허용
- 원본 페이지 위치 표시
- 매핑 근거 및 신뢰도 표시
- 드래그 또는 선택을 통한 수동 매핑
- 불필요한 매핑 제거
- 누락된 콘텐츠 확인
- 특정 목차만 다시 매핑

원본 텍스트를 목차 테이블에 복사하지 않는다. 목차와 콘텐츠의 연결은 `content_block_id`를 참조한다.

목차 수동 수정은 목차 리비전을 저장하며 자동 분석을 실행하지 않는다. 특정 범위의 재매핑은 명시적인 요청으로 실행한다.

## 4.5 Reference Library

프로젝트와 독립적인 회사 공용 자료 저장소로 관리한다.

### 기능

- 레퍼런스 문서 업로드 및 파일별 원본 보존
- 다중 파일 일괄 등록
- 지정 디렉터리의 파일 가져오기
- 자동 추출·색인
- 파일 유형·태그·분류 관리
- 키워드 및 의미 기반 검색
- 문서별 미리보기
- 레퍼런스 버전 관리
- 활성·숨김·보관 상태 관리
- 프로젝트별 사용 이력 조회
- 슬라이드와 근거 관계 조회

검색은 회사 공용 자료를 기본 대상으로 한다. 프로젝트에만 업로드된 참고 자료도 검색 대상에 포함할 수 있다. 명시적으로 공용 등록하지 않은 자료는 회사 공용 라이브러리에 자동 등록하지 않는다.

## 4.6 Template Library

프로젝트와 독립적인 회사 공용 템플릿 저장소로 관리한다.

### 기능

- PPTX 업로드
- PPT Master 기반 템플릿 추출
- 레이아웃·마스터·슬롯 분석
- 대표 페이지 미리보기
- 디자인 특징 추출
- Brand / Style / Layout / Deck 구분
- 템플릿별 태그·분류
- 적합도 검색·추천
- 템플릿 버전 관리
- 추출 실패 및 재추출 관리
- 프로젝트별 사용 이력
- 프로젝트 로컬 템플릿을 공용으로 등록

프로젝트 생성 시 업로드한 템플릿은 우선 프로젝트 로컬 자산으로 등록한다.

### 추천 후보와 선택권

1. 사용자가 업로드한 템플릿
2. 프로젝트에서 명시적으로 선택한 템플릿
3. 회사 공용 템플릿
4. 새롭게 구성한 Free Design

사용자가 지정한 템플릿은 자동 추천 결과보다 우선한다. 업로드 여부와 관계없이 사용자에게 최종 선택권을 제공한다.

## 4.7 PPT 생성

### 입력 요소

- 대상 프로젝트
- 선택한 대목차·중목차
- 적용할 프로젝트 가이드 버전
- 해당 PPT만의 추가 지침
- 템플릿 선택
- 레퍼런스 선택
- 목표 슬라이드 수 또는 분량
- 발표 대상 및 출력 형식

### 처리 단계

1. 콘텐츠 및 근거 수집
2. 슬라이드 스토리라인 생성
3. 슬라이드별 PresentationSpec 생성
4. 레이아웃 선택
5. PPT Master 기반 렌더링
6. PPTX 조립
7. Kordoc 재추출
8. 내용·근거·시각 품질 검사
9. 최종 파일 및 미리보기 저장

Workflow에서는 PresentationSpec과 개별 SlideSpec을 사용한다. 세부 스키마는 [버전 관리 대상](09-operations-delivery.md)이며, 실행 단계는 [Presentation Generation Workflow](04-workflow-engine.md)에 정의한다.

완성된 PPTX는 원본 슬라이드 파일과 함께 버전 관리한다. 개별 슬라이드가 완료되면 전체 PPTX 조립을 기다리지 않고 미리볼 수 있어야 한다.

## 4.8 PPT 채팅 편집

### 수정 범위

- 선택한 요소
- 현재 슬라이드
- 현재 중목차
- 현재 프레젠테이션 전체

### 기능

- 자연어 수정 지시
- 슬라이드 제목·본문 수정
- 다이어그램·표·이미지 구성 변경
- 슬라이드 추가·삭제·복제·순서 변경
- 원본 근거 재확인
- 수정 전후 비교
- 변경 적용·취소
- 이전 리비전 복원

채팅 수정은 기존 SlideSpec을 직접 덮어쓰지 않는다. 변경된 SlideSpec을 새로운 슬라이드 리비전으로 저장하고, 생성이 완료된 버전만 사용자에게 적용한다.

변경된 슬라이드 렌더링을 우선한다. 사용자가 최종 다운로드를 요청할 때 필요한 경우 프레젠테이션 전체를 새 리비전으로 조립한다. 미리보기 차이 확인 후 새 리비전을 확정하는 절차는 [Slide Revision Workflow](04-workflow-engine.md)를 따른다.

## 작성 방향 간소화 및 시각적 자산 검색

최신 Studio 작성 방향 입력은 선택적인 Do / Don’t 두 필드다. 빈 값이면 기본 작성 정책을 사용한다. 과거 상세 가이드 필드는 이전 리비전에서 보존하며 기존 리비전을 덮어쓰지 않는다. 새 가이드 구조는 schema_version 3으로 관리하고 이전 goal/audience/emphasis/required/storyline 등의 정보는 변환 계층에서 Do 후보, avoid는 Don’t 후보로 읽는다. 사용자 확인 없이 과거 원본을 덮어쓰지 않는다.

근거/템플릿 선택은 검색 결과 갤러리다. 파일 표지와 내부 문단·이미지·차트·장표 썸네일을 제공하고, 크게 보기와 선택을 분리한다. 파일명·버전·원본 쪽과 사용 목적을 표기하며 이미지/차트/장표 전체를 생성 자료로 담을 수 있다. 실제 객체 삽입은 Workflow 계약을 따른다.

## 프로젝트 기본 기능의 구현 단계

첫 제품 기능은 로그인 없이 공유하는 프로젝트 메타데이터 생성·조회·검색·이름 변경이다. 이름과 마감일로 프로젝트를 만들고 Studio 원본 단계에서 문서를 추가한다. 현재 프로젝트 원본 등록·추출·확인과 Do/Don’t 저장을 제공하며, PPT 생성 Workflow는 후속 범위다. 분석·PPT 생성을 위한 원본 요건은 유지한다. 개발은 각 기능의 백엔드와 실제 React 사용 흐름을 함께 완성하는 단위로 진행한다.

## 현재 Space 제품 범위

공용 Reference/Template 원본 업로드, 파일명·제목·태그 검색, 버전별 다운로드, 이름/태그 수정, 보관/복원·논리 삭제가 실제 Rust/SQLite/React로 연결되어 있다. 프로젝트에 자동 편입하지 않는다. 본문 추출·OCR·페이지 미리보기·내용 검색·템플릿 레이아웃 분석·추천은 후속 범위다. 상세 흐름은 [현재 제품 흐름](../dev-docs/02-product-workflows.md)을 따른다.

Space 레퍼런스 원본 등록은 UTF-8 HTML(`.html`, `.htm`)도 지원한다. 원본·버전·다운로드는 기존 불변 Blob 계약을 따르며 HTML을 앱에서 실행하지 않는다. HTML 변환·본문 추출·미리보기는 후속 범위다. 템플릿은 PPTX 전용을 유지한다.

## 사용자 경험 적용 범위

기능은 일반 사무직의 자료 준비·작성·검토·수정 업무 단위로 노출한다. 내부 데이터 관계와 처리 순서 설명을 사용자 작업의 선행 지식으로 요구하지 않는다. 공통 기준은 [일반 사무직을 위한 사용자 경험 계약](07-ui-design.md#일반-사무직을-위한-사용자-경험-계약)을 따른다.

## 레퍼런스 재사용 단위

레퍼런스는 문서 전체뿐 아니라 장표 한 장/여러 장, 첨부 이미지, 그룹 도식, 차트, 글·표를 후속 PPT 생성의 입력으로 제공한다. 원본 버전, 추출 ID, 페이지/장표 순서와 요소 위치를 보존한다. 원본 PPTX와 네이티브 요소 관계·미디어를 유지하며 화면용 PNG로 편집 구조를 대체하지 않는다. 본문은 content_block_id로 연결한다. 선택한 장표/요소의 순서와 원본 버전은 생성 시 명시적으로 고정한다.

현재 Space는 자료 종류별 검색·미리보기와 최대 50개 자료의 선택 순서 검토를 제공한다. 일반 문서는 페이지 이미지·추출 이미지·텍스트를 제공 가능한 범위에서 재사용한다. 레퍼런스 준비가 Template Library 등록이나 생성 덱 삽입을 자동 수행하지 않는다.

레퍼런스 추출은 Kordoc의 `dropBlankImages: true`를 사용한다. 이 옵션은 크기 하한이 아니라 흰 배경 합성 후 거의 균일한 색인 이미지(빈 판·단색 띠·옅은 배경)를 제외하는 기능이다. 작아도 형태가 있는 아이콘은 유지한다. PPT Master 경로의 개별 이미지 후보도 같은 Kordoc 구현으로 검사하며, 장표·차트·도식 전체나 원본 PPTX·패키지의 미디어 바이트는 제거하지 않는다. 처리할 수 없는 이미지 형식은 보존한다. 새 추출 프로필부터 적용하며 기존 결과를 자동 변경하지 않는다.


### 구현된 Studio 진입 범위

프로젝트 생성/선택은 Studio 원본 등록 단계로 연결한다. 프로젝트 원본은 공용 Space와 독립된 등록·불변 파일 버전을 갖고 공통 Blob 및 동일 원본/프로필 추출 결과를 공유한다. 원본 페이지 보기, 교체, 과거 원본 다운로드, 실패 재시도와 명시적 원본 확인을 제공한다. 확인은 파일 버전/추출 ID 집합에 고정하며 변경 시 오래된 확인을 완료로 사용하지 않는다. 다음 작성 방향은 선택적 Do/Don’t 리비전 저장이며 목차/PPT 생성은 후속 기능이다.


## 다른 프로젝트의 업무 자료 검색

프로젝트 원본의 범위는 모든 지원 업무 문서이며 RFP 전용으로 제한하지 않는다. 현재 원본·선택적 Do/Don’t·추가 검색어를 바탕으로 과거 프로젝트의 원본에서 파일/내용 후보를 찾고 주된 업무 관계를 판정한다. 동일 내용의 여러 프로젝트 사용 관계는 묶어 보여주고 특정 출처 버전/내용을 참고 자료로 연결한다. 현재 원본을 Space에 자동 등록하지 않으며 검색 결과 선택이 PPT 생성·삽입을 의미하지 않는다.

관계 판단은 같은 맥락, 뒷받침 자료, 재사용할 접근 방식, 차이 확인, 판단 보류를 구분한다. 사용자는 비교 전에도 직접 출처를 확인해 선택할 수 있고 판정이 기존 선택을 자동 제거하지 않는다. 모델의 임의 확률을 일치도 점수로 표시하지 않는다. 검색 범위와 미리보기의 버전을 명확히 유지한다.


### Markdown 원본 지원

공용 레퍼런스와 프로젝트 원본은 `.md`/`.markdown`을 지원한다. 원본 보존·버전·다운로드와 문서 작업 상태를 기존 경로로 제공한다. UTF-8만 허용하며 초기 크기 제한은 2 MiB다. 제목·본문·목록·코드·표·링크/이미지 설명과 원문 위치를 구조화한다. 템플릿으로는 등록하지 않는다.

Kordoc의 Markdown 출력과 입력 파싱을 구분한다. Markdown 입력은 유지보수되는 Comrak 라이브러리로 처리하고 별도 문법 파서를 만들지 않는다. HTML과 외부/로컬 리소스는 실행·로드하지 않으며 안전한 텍스트 조회를 기본으로 한다. 원본 형식별 추출 profile과 등록 단위 해석을 사용해 동일 Blob의 HTML/Markdown 결과가 섞이지 않도록 한다.


### 구현된 Studio 목차·콘텐츠 구성

원본 확인과 선택적 Do/Don’t 저장 후 발표용 대목차/중목차를 생성하거나 직접 작성한다. 두 단계·최대 24개 목차의 추가·삭제·이동·제목/설명 수정, 전체 또는 선택 목차의 자동 연결, 수동 원문 추가·제거, 다중 목차 연결, 확정과 과거 버전 조회를 제공한다. 원본·가이드 변경은 기존 결과를 보존하고 재검토 상태로 표시한다. 실제 PPT 생성은 후속 기능이다.

### 현재 PPT 생성의 제공 범위

실제 제품은 근거 확정 → 템플릿 선택 → 슬라이드별 LLM 작성 → PPTX 출력 → Kordoc 내용 재검사 → PNG 미리보기/다운로드를 제공한다. 현재 생성 단위는 마지막 목차별 한 장이며 최대 24장이다. 기본 디자인은 PPT Master 네이티브 출력, 업로드 템플릿은 기존 마스터·제목/본문 레이아웃을 적용한다. 결과를 PowerPoint에서 편집할 수 있으며 앱 내 캔버스 편집·채팅 수정은 후속 범위다. 이미지·차트·장표 삽입과 자유 분량 조절을 완료 기능으로 취급하지 않는다. 구현 계약은 [실제 PPT 생성](../dev-docs/02-product-workflows.md#실제-ppt-생성과-결과-확인)을 따른다.
