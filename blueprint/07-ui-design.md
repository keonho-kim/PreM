# UI 및 Folio 디자인

PreM 통합 제품·기술 설계서 v2.0의 **9장**과 현재 디자인 계약을 수록한다. [문서 색인](README.md)

## 현재 디자인 결정

사용자가 전체 디자인을 맡긴 요청에 따라 **Hallmark Furrow를 문서 작업에 맞게 적용한 Folio**를 사용한다. 종이·잉크·주석을 중심으로 장시간 문서 검토에 적합한 작업 공간을 만든다. 이전 Refract, Bellwater Lido, 타일, 글래스 표현을 대체한다. 라이트 전용이며 다크 테마와 전환 기능은 없다.

현재 UI 구현은 [React 프론트엔드](../frontend/src/)이며 실제 기능과 검증 범위는 [개발 문서](../dev-docs/README.md)를 따른다. [design.md](../design.md)가 화면 간 디자인 기준을 고정하고 [본개발 소스 아키텍처](02-system-architecture.md)이 기능 소유권을 정한다.

| 역할 | 기준 |
| --- | --- |
| 작업 바탕 | #F6F5F2, 매우 옅은 중립 종이 톤 |
| 콘텐츠 면 | #FFFEFA, 불투명 종이; 원문·슬라이드는 본래 색상 보존 |
| 주요 동작 | #F58254 탠저린 버튼과 #262824 잉크 |
| 글자 | #262824 기본, #51564F 보조, #60665D 메타 |
| 선택·근거 | #9C3D1E 주석 잉크, 짧은 세로선과 원문 페이지 표기 |
| 경계 | #DCDED6 구분선, #7D8177 입력 경계 |
| 재질 | 타일·유리·블러·그레인 없음. 문서 종이와 다이얼로그에만 작은 중립 그림자 |
| 모서리 | 명령 8px, 작업 면 12px, 종이 2px |

사진, 가상 실적, 후기, 장식 차트를 추가하지 않는다. 실제 원문 페이지와 슬라이드가 화면의 시각적 중심이다.

## 원본 토큰과 생성 출력

[design/refract.tokens.json](../design/refract.tokens.json)이 유일한 팔레트 원본이다. 파일명은 기존 생성기 경로 호환을 위해 유지하며, 내용은 Folio이다.

```text
design/refract.tokens.json
             │
             ▼
scripts/generate-design-tokens.mjs
             └── frontend/src/app/styles/theme.generated.css
```

- `pnpm tokens`: 두 실행 환경의 CSS 생성. 타일 배경은 더 이상 생성하거나 사용하지 않는다.
- `pnpm tokens:check`: 원본과 생성 결과 확인, 품질·빌드 검사에 포함.
- 폰트 로딩, 간격, 배치, 상호작용은 UI 소유자가 관리한다.
- `--glass-*`는 기존 소비자 호환용 표면 이름이며 값은 불투명 Folio 토큰이다.
- 앱 실행 중 패키지 설치나 토큰 생성은 수행하지 않는다.

### 화면 구성

- 공통: 최대 1600px, 32px 작업 여백, 휴대폰 16px. Home·Studio·Space·Admin의 상단 고정 내비게이션, 전역 사이드바는 없으며 Admin 내부에는 접을 수 있는 로컬 사이드 메뉴를 제공한다.
- Home: 상태 탭·검색·정렬과 열린 표. 이름과 행 동작이 읽히는 구분선 중심 구성.
- 개요: 큰 슬라이드 미리보기와 준비 상태 목록, 아래에 원본과 최근 작업.
- 문서: 가로 파일 선택과 페이지 갤러리. 뷰포트에 접근한 샘플 미리보기만 생성하며 크기를 먼저 확보.
- 가이드: 선택적인 Do / Don’t 두 입력, 아래 리비전 disclosure.
- 목차: 가로 목차 선택 후 연결 콘텐츠와 원문 근거. 근거에는 페이지와 짧은 주석선 사용.
- 레퍼런스: 파일/콘텐츠 검색 갤러리와 확대 미리보기, 템플릿: 검색 가능한 슬라이드 proof.
- PPT 편집: 중립 작업대의 슬라이드, 아래 가로 필름스트립과 수정 폼. 기존 리비전·비교·적용 동작 보존.
- Studio: 프로젝트 전환, 확인 상태를 관리하는 6단계 스테퍼와 각 단계의 기존 작업 화면.
- Space: 공용 템플릿·레퍼런스 업로드와 자산별 처리 진행 바. 프로젝트 원본과 별도 관리.
- Admin: 시작 시 CLI 토큰을 입력한 접속자에게 팀 공용 모델·운영 설정을 제공한다.

### 서체와 상호작용

로컬 Red Hat Display 500의 28px 화면 제목, Red Hat Text 16px 본문과 14px 라벨을 사용한다. 숫자는 tabular-nums, 한글은 시스템 산세리프 폴백이다. OFL 라이선스를 함께 제공한다.

명령은 최소 44px, 거친 포인터 48px를 유지한다. ‘문서 추가’는 실제 업로드 대화상자를 열며, 개요에서는 보조 버튼, 문서 화면에서는 주요 버튼이다. 네이티브 dialog의 포커스·Esc·복귀를 유지한다. 폼의 라벨과 오류, 표 caption·헤더, 키보드 스크롤 영역을 보존한다.

가이드 저장과 기존 결과 재생성은 별도 동작이다. 수정안은 비교 후 적용하고, 기존 리비전은 유지한다. 샘플 처리임을 명확히 알린다. 실제 PDF 렌더링과 서버 페이지네이션은 향후 제품 구현이다.

### 접근성 및 검증

- 일반 글자 4.5:1, 필수 아이콘·입력 경계·포커스 3:1 이상.
- 기본 표면은 불투명. forced-colors에서 시스템 색과 실제 경계를 사용한다.
- 색상만으로 상태를 표시하지 않고 텍스트·아이콘·밑줄·ARIA 상태를 함께 사용한다.
- 최소 크기 Grid 트랙과 명시적 종이 종횡비, 읽기 순서에 맞는 DOM을 유지한다.
- 모션은 조작 피드백에 한정하며 reduced-motion을 따른다.
- 갤러리 observer와 폴백 이벤트는 재렌더·화면 이탈·페이지 종료 시 정리한다.
- 현재 캡처는 `tests/.artifacts/captures/folio/`, 이전 Refract 이미지는 역사 자료다.
- 개발 도구는 `tests/helpers/`, 임시 파일·보고서는 `.artifacts/`; `data/`에는 앱 데이터만 저장한다.

## 9.1 전체 메뉴 구조

```text
Home                        프로젝트 목록·생성·검색
Studio                      프로젝트별 PPT 제작
 ├─ 1 원본 등록             업로드 후 진입
 ├─ 2 작성 방향             프로젝트 가이드
 ├─ 3 목차·콘텐츠           매핑과 근거 검토
 ├─ 4 근거 선택             사용할 레퍼런스
 ├─ 5 템플릿 선택           적용할 디자인
 └─ 6 생성·편집             결과물과 리비전
Space                       프로젝트와 독립적인 공용 자산
 ├─ 레퍼런스                등록·추출·색인 진행 상태
 └─ 템플릿                  등록·레이아웃 추출·검증 진행 상태
Admin (CLI 토큰으로 접근하는 팀 공용 설정)
 ├─ AI 연결
 ├─ 모델 라우팅
 ├─ 작업 현황
 └─ 시스템 상태
```

Studio의 프로젝트 개요·작업 이력은 프로젝트 문맥 링크로 유지한다. 원본 등록과 프로젝트 생성 후에는 Studio의 1단계로 이동한다. 전역 메뉴는 모든 화면에서 유지한다.

스테퍼는 네모 카드 대신 원형 마커를 선으로 잇는 타임라인이다. 단계명·상태는 마커 아래에 표시하고, 현재 단계는 링과 밑줄, 완료 단계는 체크로 구분한다. 연결선은 양옆 단계가 모두 완료된 구간만 진하게 표시한다. 스테퍼는 현재 위치와 완료 상태를 구분한다. 방문만으로 완료되지 않으며, ‘확인하고 다음’은 저장된 문서 목록·가이드 리비전·목차 리비전·선택 자산을 확인한다. 입력이 바뀌면 해당 단계는 ‘변경됨’으로 표시한다. 저장하지 않은 가이드가 있으면 먼저 저장하도록 안내하며, 새 결과물을 자동 재생성하지 않는다.

Space는 자산별 및 전체 처리 진행 바를 사용한다. 알 수 없는 실제 진행률은 확정 백분율 대신 불확정 상태로 표시해야 한다.

제품은 사용자 계정·역할 계층 없이 Admin만 CLI 토큰으로 보호하며 회사 네트워크에서도 접근을 제한한다.

## 9.2 프로젝트 목록

| 표시 정보 | 지원 기능 |
| --- | --- |
| 프로젝트 이름·상태 | 프로젝트 생성 |
| 원본 문서 수 | 검색·정렬 |
| 최신 프로젝트 가이드 버전 | 상태 필터 |
| 목차 분석 상태 | 프로젝트 복제 |
| 마지막 PPT 생성 시간 | 보관·삭제 |
| 실행 중 Workflow | 작업 진행 상황 확인 |
| 최근 수정 시간 | 해당 프로젝트로 이동 |

프로젝트는 검색·필터를 가진 표로 표현한다. 상태 요약만을 위한 카드 격자는 만들지 않는다.

## 9.3 프로젝트 상세

```text
┌──────────────────────────────────────────────────────┐
│ PreM       Home  Studio  Space  Admin              │
├──────────────────────────────────────────────────────┤
│ 프로젝트 전환                     개요 / 작업 이력    │
│ 원본 → 방향 → 목차 → 근거 → 템플릿 → 생성·편집        │
│ 현재 단계의 전체 너비 작업 영역                       │
│                       이전 / 확인하고 다음            │
└──────────────────────────────────────────────────────┘
```

전역 헤더는 스크롤 중에도 상단에 남는다. 프로젝트 문맥과 스테퍼는 Studio 본문에 속한다. 좁은 화면에서는 제작 단계를 가로 스크롤하고 현재 단계가 보이도록 한다. Space에는 스테퍼를 표시하지 않는다.

적용 가이드와 입력 버전을 숨기지 않는다. 제작 단계 검토 완료와 백그라운드 생성 실행 단계는 다른 상태이며 따로 표시한다.

## 9.4 문서 뷰어

```text
문서 선택: [설계서.pdf] [가이드.docx] [참고자료.pptx]

선택 문서 / 페이지 수 / 분석 상태
[ 1쪽 미리보기 ] [ 2쪽 미리보기 ] [ 3쪽 미리보기 ] …
[ 4쪽 미리보기 ] [ 5쪽 미리보기 ] [ 6쪽 미리보기 ] …

페이지 선택 → 크게 읽기 / 이전·다음 페이지 / 닫기
```

원본 문서는 페이지 갤러리로 탐색한다. 종이 비율을 먼저 확보하고, viewport에 가까운 페이지만 미리보기를 준비한다. 문서 변경·재렌더·경로 이탈 시 observer와 대체 이벤트를 정리한다. IntersectionObserver 미지원 환경에서도 가까운 페이지를 확인하는 작은 대체 경로와 즉시 열 수 있는 페이지 버튼을 유지한다.



페이지 이동, 확대·축소, 텍스트 선택, 목차 연결 확인, 원본과 추출 결과 비교, OCR 재실행, 오류 페이지 표시를 제공한다.

페이지의 실패를 문서 전체의 실패와 구분하고 원본 다운로드를 유지한다. 흰 문서 표면과 밝은 중립 작업 캔버스를 구분한다.

## 9.5 목차·콘텐츠 매핑 화면

```text
목차 선택: [대목차 1] [중목차 1-1] [중목차 1-2] …
┌────────────────────────────┬─────────────────────────┐
│ 선택 목차에 연결된 콘텐츠   │ 원문 근거                │
│ 문단 / 표 / 연결 관리       │ 해당 블록과 위치          │
└────────────────────────────┴─────────────────────────┘
```


목차 트리 편집, 중목차 선택, 연결 콘텐츠 확인, 콘텐츠 추가·제거, 원문 이동, 누락 콘텐츠 확인, 선택 목차 재분석을 제공한다.

동일 블록의 다중 매핑과 근거·신뢰도를 표시한다. 수동 수정 저장과 선택 범위 재분석은 별도 동작이다.

## 9.6 레퍼런스 탐색 화면

- 검색 질의
- 후보 레퍼런스 목록
- 관련성 평가 결과
- 원본 미리보기
- 근거 블록
- 선택·제외·고정
- Workflow 단계별 상태

공용·프로젝트 로컬 범위, 사용한 버전, 근거 부재를 확인할 수 있게 한다. 근거가 없으면 없는 상태로 표시한다.

## 9.7 템플릿 탐색 화면

- 업로드 템플릿
- 공용 라이브러리
- 추천 템플릿
- 대표 레이아웃 미리보기
- 템플릿 상세 정보
- 템플릿 선택
- 추출 상태 및 오류

템플릿 미리보기는 실제 추출 결과를 사용한다. 사용자 지정 템플릿의 우선권과 최종 선택권을 유지한다.

## 9.8 PPT 생성 화면

생성 전에 대상 목차, 적용 프로젝트 가이드, PPT별 추가 지침, 템플릿, 레퍼런스, 예상 슬라이드 수를 설정한다. 전체 입력 계약은 [PPT 생성 기능](03-product-features.md)을 따른다.

생성 중에는 사용자가 이해할 수 있는 진행 상태와 취소·이어가기 행동을 표시한다. 내부 실행 그래프는 노출하지 않는다. 완료된 개별 슬라이드는 전체 PPTX 조립을 기다리지 않고 미리볼 수 있어야 한다.

진행 중인 결과와 최종 검증·확정 결과를 구분한다. 품질 검사 실패는 해결되지 않은 오류와 재시도 범위를 함께 보여준다.

## 9.9 PPT 편집기

```text
PPT 제목 / 가이드·목차 버전 / 편집 도구 / 내보내기
┌────────────┬───────────────────────┬─────────────────┐
│ 슬라이드 ＋│                       │ AI 대화 / 참조  │
│ 세로 목록  │   슬라이드 캔버스     │ 메시지 이력     │
│ 우클릭 메뉴│                       │ 수정안 적용·취소│
│ 순서 이동  │                       │ 선택 대상·입력창│
└────────────┴───────────────────────┴─────────────────┘
```

좌측 슬라이드 목록과 우측 AI/Reference 패널은 독립적으로 접는다. 작은 화면에서는 목록이 가로로, 대화 패널은 캔버스 아래로 배치된다. 텍스트 속성은 캔버스 직접 편집과 상단 도구에서 변경하고, 원문 근거는 Reference 탭에서 확인한다.

AI 탭은 메시지 이력과 하단 입력창으로 구성한다. 캔버스의 제목·본문·삽입 텍스트·이미지·도형 선택을 수정 대상으로 표시한다. Ctrl+클릭 또는 macOS ⌘+클릭으로 다중 선택·해제하며, 일반 클릭은 단일 선택, 빈 캔버스 또는 선택 해제 버튼은 현재 슬라이드 범위로 전환한다. 목차·전체 범위 선택 폼은 이 대화 화면에 두지 않는다.

제품 편집기의 대화 패널에는 AI 선택기와 수정 범위 선택기를 두지 않는다. 객체 선택이 없으면 현재 장표 전체를 대상으로 하며, 명시적으로 선택한 여러 장표는 일괄 대상으로 유지한다. 현재 대상만 읽기 전용 문구로 표시한다. LLM은 서버가 해당 발표자료의 연결에서 자동 결정하고 사용할 수 없으면 Admin 설정 확인을 안내한다. 생성 단계의 작성 모델 설정과 편집 대화는 별개다.

전/후 비교와 되돌리기는 중앙 PPT 확대 도구의 왼쪽에 아이콘으로 배치한다. 비교는 누르고 있는 동안 이전 장표를 표시하며 놓으면 복귀한다. 키보드와 터치, 입력 취소·포커스 이탈도 처리한다. 되돌리기는 현재 편집 세션의 최근 3단계까지이며, 서버 참조 캐시는 화면 이탈·프로젝트 변경·탭 종료 시 삭제한다. 비정상 종료는 비활성 만료로 정리한다. 확정된 PPT 버전은 보존하고 복원은 새 리비전으로 기록한다. 채팅의 별도 비교·결과 보기 버튼은 제공하지 않는다.

전송 시 선택 요소 키, 슬라이드 및 리비전을 고정한다. 대화 안에서 수정 전후를 검토하고 적용·취소하며, 선택 변경이 기존 수정안의 대상을 바꾸지 않는다. 적용은 새 불변 리비전을 만들고, 다른 변경이 발생한 수정안은 재요청을 안내한다. 선택하지 않은 요소와 다른 슬라이드는 유지한다.

메시지와 작성 중 문구는 프로젝트·프레젠테이션·슬라이드별로 분리한다. Enter로 전송, Shift+Enter로 줄바꿈하며 한글 조합 확정 Enter는 전송하지 않는다. 다중 선택은 채팅 수정 범위를 지정하며 그룹 이동·그룹화·일괄 도구 조작은 후속 구현이다. 실제 PPTX 다운로드는 제품 계약이다.

## 9.10 Admin 화면

제품 Admin은 상단 공통 Nav 아래에 로컬 사이드 메뉴를 둔다. 현재 메뉴는 **모델 연결 / 문서 처리 / 시스템 상태**이며 미구현 기능은 작동하는 메뉴로 표시하지 않는다. 모델 연결에는 **LLM / Decision** 탭을 항상 표시하고, 등록된 연결에는 **연결 설정 / 처리 설정 / 연결 테스트 / 판정 테스트 / 요청 이력** 상세 탭을 둔다. 아래 표의 상세 모델 라우팅·Workflow·백업·스토리지 진단은 후속 기능 요구사항이다.

사이드 메뉴는 의미 있는 링크와 현재 페이지 표시를 사용하고 shadcn Collapsible로 접는다. 작은 화면에서는 같은 메뉴를 본문 위에 배치하며 접기·펼치기를 유지한다. 상세 패널은 shadcn Tabs가 키보드와 ARIA를 담당한다. section/provider/tab 쿼리를 URL로 보존하고 탭은 방향키로 초점을 이동한 뒤 Enter/Space로 활성화한다. 탭 변경만으로 실행 중인 테스트를 취소하거나 결과를 지우지 않는다. 이력 polling은 이력 탭을 볼 때만 수행한다.


| 화면 | 기능 |
| --- | --- |
| AI 연결 | 연결·수정·활성화·테스트 |
| 업무별 AI | 작업별 모델 선택 |
| 작업 현황 | 실행 상태·실패·재시도 |
| 서비스 상태 | 자료 준비·PPT 만들기·AI 연결의 이용 가능 여부와 필요한 조치 |
| Backup Status | 백업·복구 검사 상태 |

Provider 설정 저장과 연결·Vision·Tool Calling·Structured Output 테스트를 구분한다. API Key를 다시 노출하지 않는다. 설정 버전과 새 요청 반영 상태를 보여준다.

제품 Admin은 별도 사용자 계정 없이 CLI 토큰으로 접근하며 설정 자체는 팀 공용이다. [운영 네트워크 보호](09-operations-delivery.md)는 여전히 필요하다. 공용 자료·템플릿 관리는 Space로 분리한다.

## 구현 후 디자인 검증

- 각 화면의 로딩·비어 있음·오류·정상 상태, 키보드 조작, 포커스, 대비, 좁은 화면 패널 전환을 검증한다.
- 실제 CSS의 첫 비어 있지 않은 줄에는 Hallmark stamp, 다음에는 critique, 이후 필요한 waiver를 기록한다. 토큰은 단일 기준 파일에서 관리한다.
- 프론트엔드가 구현되면 `sloplint <구현 파일 또는 폴더> --scope app --genre modern-minimal --render --url <실행 URL>`로 검사한다. Floor 실패를 해결하고 Reflex 발견은 수정 또는 근거를 기록한다.
- 실제 제품 화면의 렌더링·상호작용과 OCR·LLM·PPTX 처리 결과를 함께 검증한다. 현재 캡처 위치는 tests/.artifacts/captures/folio/이며 제품 기능 검증은 해당 기능 구현 시 수행한다.

## 최신 작성 방향·검색 UX

작성 방향은 Do / Don’t 두 textarea로 구성하고 모두 선택 입력으로 둔다. 자세한 필드 작성 부담을 주지 않으며 저장과 기존 PPT 재생성은 분리한다.

근거와 템플릿은 목록 대신 시각적 검색 갤러리로 보여준다. 검색창 아래 파일/문단/이미지/차트/장표 전체 필터를 제공한다. 썸네일은 크게 보기 버튼, 선택은 별도의 명시적 컨트롤로 구성한다. 파일명만 보여주지 말고 원본 내용·위치·버전을 함께 보여준다. 선택 바구니에는 생성에 사용할 자료와 삽입 방식이 표시된다. 템플릿은 대표 장표와 검색에 일치한 내부 레이아웃을 보여준다.


## Search and editor inspector update

Evidence discovery now uses vertical news-style rows: left thumbnail, upper-right title and lower-right excerpt. Actual query matches in titles, excerpts and filenames are highlighted; body matches rank before filename/title-only matches. No invented semantic similarity percentage is displayed.

The editor places the visual Reference gallery in a right task inspector alongside an AI conversation tab. Switching tabs preserves the existing form DOM and draft. Current slide source evidence determines sample candidates. Selecting a candidate creates a new revision with sourceInsertions for that slide only. This is an insertion plan, not native PPTX insertion. On phones the inspector stacks below the canvas and filmstrip. This update supersedes the earlier gallery-only evidence-search and lower-composer layout.

## Editor workbench refinement

The editor uses a vertical slide thumbnail list on the left, canvas in the center and AI/Reference inspector on the right. The thumbnail list shows each slide number and title and reveals the selected slide within its own scroll region. The timeline remains compact, expanded and sticky below global navigation in every Studio stage, preserving all earlier stage links. Controls are grouped into slide commands and revision/navigation commands. On tablets the inspector stacks below; on phones the slide list becomes a horizontal strip above the canvas. This supersedes the earlier lower-filmstrip arrangement.

### Independent editor panels

The left slide list and right AI/Reference inspector each have an independent collapse/reopen button outside the panels. Either or both panels can be hidden; the canvas expands into the available space. Keep panel DOM and tab/draft state intact, remove hidden controls from the focus order, and preserve visibility across editor rerenders within the browser session. Refresh resets the UI.

## Direct-edit baseline

Secondary actions use Lucide icons with names and tooltips. Slide addition moves to the left list header; duplicate/delete/reorder actions live in a context menu with keyboard access. Empty/gap targets show insertion lines, and drag handles provide pointer ordering with Escape cancellation and menu/keyboard alternatives. The list header stays outside the scrolling thumbnails to avoid hiding drag handles.


## 프로젝트 카드 갤러리와 마감일

Home은 데스크톱 3열·중간 화면 2열·휴대폰 1열, 페이지당 6개 프로젝트를 제공한다. 마감일(Due Date)은 등록 시 shadcn Calendar/Popover로 선택하는 단일 날짜다. Input의 YYYY-MM-DD 직접 수정도 같은 날짜 검증을 거친다. 카드에서 마감일과 D-Day를 확인하며, 검색도 `마감일` 달력 한 칸으로 해당 날짜와 일치하는 프로젝트를 찾는다. 검색 필터는 입력란을 누르거나 아래 방향키를 사용해 달력을 열며 직접 입력도 허용한다. 시작/끝이라는 기간 입력은 제공하지 않는다. 실제 제품은 저장된 기본 정보만 보여주며 문서/PPT 기능 구현 전에 샘플 수치나 미리보기를 만들지 않는다.

프로젝트 선택 전 Studio는 Home 갤러리를 공유하며 첫 프로젝트 생성과 저장된 작업 단계 확인을 제공한다. Home 상단에는 프로젝트 제목·설명과 생성 버튼을 배치한다. 별도의 공유 표제나 하단 공유·서버 상태 안내는 두지 않는다. 우클릭/점 세 개 메뉴의 생성·이름 변경·정보 복사·보관/복원·논리 삭제는 유지한다. 우측 하단은 작업 패널과 토스트가 사용한다.

## 제품 컴포넌트 적용 기준

일반 UI는 공식 shadcn/ui 컴포넌트를 우선하고 AI 대화·도구·근거 UI는 공식 AI Elements 패턴을 우선한다. Dialog·Alert Dialog·Context Menu·Dropdown Menu·Calendar/Date Picker·입력·탭의 접근성 및 상호작용은 선택한 primitive가 담당한다. 별도의 수동 focus trap·메뉴 키보드 처리를 중복 적용하지 않는다. 이 기준이 제품의 native 컨트롤 우선 권고보다 우선한다.

AI 대화는 Chat/Message/Message Scroller와 Prompt Input으로 구성하고 Reference의 근거는 Sources/Inline Citation으로 연결한다. Tool/Plan/Task/Confirmation은 실제 서버 이벤트와 확인이 존재할 때만 보여준다. 모델 내부 추론 대신 공개 가능한 진행 요약을 표시하며 임의 진행률을 만들지 않는다. 구성 요소 ID·프로젝트/deck/slide·리비전 고정과 변경 미리보기·적용 계약은 그대로 유지한다. 현재 실제 화면의 전환 완료 여부는 [디자인 구현 문서](../dev-docs/05-design-accessibility.md), 도입 근거와 의존성은 [의존성 명세](../dev-docs/08-dependencies.md)를 따른다.

## 제품 Space 종류 필터

Space 상단은 **전체 | 레퍼런스 | 템플릿**으로 구성하고 전체를 기본 선택한다. 전체 목록은 서버의 통합 정렬·검색·페이지 분할을 사용하며 각 카드에서 실제 종류를 구분한다. 전체의 업로드 명령은 등록 종류 선택을 제공한다. 탭 변경은 검색어·상태를 유지하고 페이지를 초기화하며 각 항목의 편집·다운로드는 원래 종류를 사용한다. 구현 형식 지원과 분석 미구현 범위는 [제품 흐름](../dev-docs/02-product-workflows.md)을 따른다.

우측 상단 알림 아이콘을 제거하고 작업 진행·완료·실패는 우측 하단 패널에 표시한다. 일반 알림은 그 위의 짧은 토스트로 표시한다. 탭별 작업 범위와 공용 자산 정책은 유지하며 새로고침 이후 알림 복원은 현재 범위가 아니다.

작업 패널은 shadcn Collapsible + Item + Progress, 알림은 shadcn Sonner로 구성한다. 접기·닫기는 전송을 취소하지 않고 닫은 작업은 작은 런처에서 다시 연다. 패널 집계는 업로드한 파일 버전의 문서 처리 결과를 따른다. 완료 항목을 정리해도 진행·실패·설정 대기 항목은 남기고, 모두 정리되면 빈 상태를 표시한다. 새 작업은 패널을 자동 표시하되 포커스를 빼앗지 않는다. 토스트와 작업 패널, 생성 명령은 겹치지 않아야 한다.

## Space 템플릿 미리보기 계약

자산을 여는 기본 화면은 사용자가 디자인을 확인하는 미리보기다. 템플릿 장표를 크게 표시하고 선택 가능한 썸네일 갤러리와 이전·다음 탐색을 제공한다. 준비·완료·재시도는 일상 용어로 안내한다. 검증 화면, 네이티브 구조·슬롯 목록, 판정 모델, 체크포인트, 원시 오류 코드 및 분석 번들 다운로드를 일반 자산 화면에 노출하지 않는다.

템플릿은 PPT Master 템플릿 추출과 미리보기 생성을 수행한다. 레퍼런스는 PPTX 여부로 템플릿 추출 가능성을 확인한 뒤 내용을 추출하며 템플릿으로 자동 등록하지 않는다. 대표 미리보기는 즉시 로드하고 썸네일은 지연 로드한다. 원본 장표 색상·비율을 유지하고 키보드로 선택·이동·닫기가 가능해야 한다.


## 일반 사무직을 위한 사용자 경험 계약

### 대상과 업무

주 사용자는 일반 사무직이며 기술 배경을 전제하지 않는다. 대표 업무는 분기 보고, 회의 준비, 제안서 구성, 온보딩·교육자료 작성이다. Home·Studio·Space·Admin 명칭은 유지하되 각 화면 제목과 행동은 한국어 업무 표현으로 안내한다. Admin은 보조적인 팀 설정 공간이며 개발 콘솔로 제공하지 않는다. 이 구분은 로그인·권한 체계 추가를 의미하지 않는다.

### 정보 계층과 용어

1. 첫 화면에는 현재 자료와 핵심 행동을 둔다. 문서·장표 미리보기를 내부 메타데이터보다 우선한다.
2. 상세한 저장 기록·사용한 자료·연결 설정은 필요할 때 펼친다. 완료한 업무의 버전은 보존하되 화면 곳곳에 번호를 반복하지 않는다.
3. 처리 상태는 대기·준비 중·완료·취소·다시 시도로 표현한다. 사용자가 확인하는 작성 단계와 서버 내부 실행 단계는 구분한다. 서버 노드 그래프를 업무 진행 표시로 사용하지 않는다.
4. 오류는 무엇을 하지 못했는지, 원본/작성 내용이 유지되는지, 사용자가 할 수 있는 행동을 안내한다. 코드·경로·모델 응답·스택 추적·재시도 구현은 노출하지 않는다.
5. 작성 요청은 선택 입력인 두 항목으로 유지한다. 전문 프롬프트, 판정 기준 JSON, 모델 옵션을 작성자에게 요구하지 않는다.

| 내부 개념 | 사용자에게 보여줄 표현·행동 |
| --- | --- |
| Project Guide / guide revision | 작성 방향 / 저장 기록 |
| Content block / mapping | 내용 / 이 목차에 담기 |
| Reference retrieval / ranking | 참고 자료 찾기 / 자료 미리보기 |
| Template manifest / slot extraction | 디자인 선택 / 장표 미리보기 |
| Workflow / node / checkpoint / retry | 만드는 중 / 다시 시도 / 이어가기 |
| Revision / commit / rollback | 이전 내용 / 적용 / 이 버전으로 되돌리기 |
| Provider / routing | AI 연결 / 업무별 AI |
| Extraction / OCR / schema validation | 자료 준비 중 / 내용을 읽지 못했습니다 |

이 표는 화면 설계 기준이다. 원문·업로드 파일·사용자가 작성한 내용에 포함된 용어를 일괄 치환하거나 감추지 않는다. 출처·페이지·파일명·날짜·실제 파일 형식처럼 결과 확인에 필요한 정보는 보존한다.

### 관리 설정과 샘플 체험

연결 주소, 사용할 AI 이름, 인증 키처럼 설정에 필요한 외부 서비스 입력은 Admin의 명확한 상세 항목으로 제공한다. 내부 DB·Blob·worker·lease·스키마·LLM 판정 과정을 일반 관리자 안내로 옮겨서 노출하지 않는다. 상세 기술 진단은 운영 문서와 서버 로그가 담당한다.


### 화면별 수용 기준

- Home: 프로젝트와 마감일을 보고 새 작업 또는 이어 할 작업을 찾을 수 있다.
- Studio: 자료 추가 → 작성 방향 → 목차 정리 → 참고 자료 → 디자인 선택 → PPT 만들기의 업무 단계로 이동한다. 저장하지 않은 입력 보호와 변경 후 재확인은 유지한다.
- 문서·참고 자료: 페이지와 내용이 먼저 보이며 출처를 확인할 수 있다. 블록 ID·검색 인덱스·모델 점수는 노출하지 않는다.
- PPT 편집: 장표·편집 도구·대화가 중심이며 변경 기록은 요청할 때 연다. 선택 요소만 수정하는 범위는 명확히 표시한다.
- Space: 자료·템플릿 미리보기와 준비 상태를 제공한다. 검증 화면이나 추출 구조 목록을 기본 화면으로 사용하지 않는다.
- Admin: 팀 설정과 작업 결과를 이해할 수 있어야 한다. 사용자가 내부 실행 단계를 해석할 필요가 없어야 한다.

검증은 화면 본문뿐 아니라 대화 상자·빈 상태·오류·토스트·진행 패널·접근성 이름까지 포함한다. 실제 일반 사무직 대상의 사용성 검증은 자동 브라우저 테스트와 별도 수용 항목이다.

## 연결별 요청 처리 설정

본개발 Admin의 연결 상세는 처리 설정 탭에서 동시 처리 수·대기 가능한 요청 수·최대 대기 시간을 조절한다. 현재 처리·대기 수를 표시하되 요청 내용이나 내부 실행 구조는 노출하지 않는다. 설정 충돌과 저장 오류는 입력을 보존하고 최신 설정 확인·재시도를 제공한다. 화면에 없는 동안 상태 polling을 중지한다.

Admin 사이드 메뉴는 **일반 / LLM 연결 / Decision Model 연결** 세 개다. LLM 연결에는 생성용 Provider만, Decision Model 연결에는 구조화 출력 LLM과 전용 Decision Provider를 제공한다. 모델 선택란을 열면 현재 입력한 주소·키로 목록을 조회하며 LLM/Decision 유형을 표시한다. 저장된 연결 선택기는 기존 설정 간 전환과 추가 연결 구성을 담당한다. 판정 테스트와 공통 판정 연결 선택은 Decision Model 연결에만 둔다. 문서 처리·자료 찾기는 하나의 공통 판정 설정을 사용하며 미설정/비활성/미지원 연결이면 실행하지 않는다. 토큰 인증은 유지하며 인증 완료 배너·잠금 버튼·팀 공용 설정 문구는 표시하지 않는다.

조회는 저장 전 임시 연결 정보로 수행한다. 저장된 주소·키는 재표시하지 않으며 기존 연결에서 빈칸은 유지다. 주소·키·Provider가 달라지면 조회 결과를 무효화하고 새 조회를 요구한다. 취소·화면 이탈 시 브라우저 요청을 중단하고 늦은 결과는 반영하지 않는다. 키는 폼 수명 동안만 보관하며 Query 캐시·URL·로그에 넣지 않는다. 실제 서버 요청은 제한 시간까지 지속될 수 있다. 새 연결은 모델 선택 후 설정 저장으로 등록하고, 기존 변경은 확인창에서 대상과 변경 항목을 확인한 뒤 저장한다. 조회·탭 전환만으로 저장·추론·모델 로드·재생성을 실행하지 않는다.

LM Studio 목록은 네이티브 `/api/v1/models`의 `llm`과 `decision`을 구분하고 로드된 instance ID를 우선한다. 로드되지 않은 모델은 서버가 반환한 key를 사용하며, 선택이 로드 또는 실행 가능성을 보장하지 않는다. 다른 Provider도 자체 모델 목록 API와 인증 규격을 사용한다. 서버가 기능 정보를 제공하지 않는 경우 목록만으로 Decision·Vision·Tool Calling 지원을 확정하지 않는다. 기존 변경의 버전 검사, 키 암호화, 실행 중 요청의 설정 고정, 모델별 처리 한도는 유지한다.

## Space 재사용 자료 보기

레퍼런스 미리보기에 **PPT에 쓸 자료**를 제공한다. 장표·페이지/그림/글·표 필터와 문서 안 키워드 검색, 원본 위치 표시를 사용한다. 시각 자료는 썸네일, 글은 읽을 수 있는 본문으로 표현하며 선택 버튼을 미리보기와 분리한다. 최대 50개를 선택한 순서로 크게 모아 볼 수 있다. 선택은 현재 화면에만 유지되고 PPT 자동 삽입을 의미하지 않는다. 미리보기가 개별 요소 대신 원본 페이지를 보여주는 경우 명확히 안내한다. gallery 이미지는 공간을 미리 확보하고 지연 로딩하며 본문 스크롤 영역은 이름과 키보드 초점을 제공한다. native locator·Blob·패키지·체크포인트 등 개발 용어는 노출하지 않는다.


## 구현된 Studio 원본 단계

Home 프로젝트 카드와 생성 완료는 `/studio/{project_id}`로 연결한다. 전역 Nav 아래 프로젝트 선택기와 연결된 원형 단계 표시를 사용한다. 원본 등록·작성 방향·목차 및 내용·근거 단계를 제공하며 템플릿과 생성 단계는 준비 중으로 표시한다. 원본 카드는 실제 파일명/형식/크기/버전/준비 상태를 보여주고 메뉴에서 교체·버전·다운로드·제거를 제공한다. 미리보기는 페이지 갤러리를 기본으로 열며 지연 로딩과 형식별 미리보기 없음 상태를 유지한다. 현재 원본 집합을 명시적으로 확인한 뒤 선택적 Do/Don’t를 작성한다. 일반 화면에서 해시·프로필·scope·SQL·판정 모델 같은 내부 저장 용어는 표시하지 않는다.


작업 패널은 데스크톱에서 우측 하단에 배치하고, 640px 이하에서는 안전 영역을 고려한 하단 전체 폭 도크로 전환한다. 패널 높이만큼 문서 끝과 스크롤 여백을 확보하여 마지막 작업 버튼이 가려지지 않도록 한다. 펼침·접힘·닫힌 런처 상태와 다른 경로로 이동한 후에도 같은 규칙을 적용하며 패널이 사라지면 여백을 해제한다.


### 근거 단계의 추가 검색

Studio 근거 단계는 선택한 근거를 기본으로 표시하고 추가 검색에서 후보를 모은다. 문서/내용 후보 목록 옆에 선택한 자료의 원문/비교 자료를 보여준다. 방문이나 검색 완료만으로 근거 확정을 표시하지 않는다. 실제 일치하는 구절만 강조하고 관계 표시는 사용자 언어로 번역한다. 소속 프로젝트와 원본 버전, 미리보기, 참고 선택을 구분한다. Native highlight 지원 여부에 따라 안전한 React mark fallback을 사용하고 페이지 전환 시 소유한 범위만 해제한다.


### Space 통합 검색

검색 범위는 회사 공용 Space의 레퍼런스·템플릿으로 한정한다. 상단 공통 검색 진입과 독립 검색 결과 페이지를 제공하고, 검색 입력을 문서 미리보기 모달의 주 작업으로 배치하지 않는다. 왼쪽 썸네일, 오른쪽 제목·출처·일치 본문의 뉴스형 행과 실제 구절 강조를 사용한다. 파일 정보/본문·자료 종류·보관 상태 조건과 페이지를 URL에 유지한다.

결과를 선택하면 원본 버전·페이지가 고정된 독립 문서 화면으로 이동하며 동일한 조건의 결과로 돌아갈 수 있어야 한다. 프로젝트 원본은 포함하지 않는다. 템플릿은 현재 이름·태그로 찾고 본문 색인은 후속 구현 범위다. 기존 Studio 관계 비교는 별도 명시적 작업으로 유지한다.


### 목차·내용 단계 구현

상단 Studio stepper의 세 번째 단계는 수평 목차 선택을 한 곳에 두고 사용할 내용과 원문 근거를 나란히 제공한다. 선택한 목차에 집중하며 전체 입력 폼을 상시 펼치지 않는다. 목차 구조 편집과 원문 추가는 필요할 때 여는 대화상자로 제공하고 AI 구성 도구는 접을 수 있다. 진행·오류 상태는 도구가 접혀도 보인다. 모델을 설정하지 않아도 직접 작성할 수 있다. 제목·설명·상위 목차·순서를 수정하고 원문을 여러 목차에 연결한다. 확정은 저장 및 원문 연결을 확인한 별도 행동이며 방문이나 AI 완료로 표시하지 않는다. 일반 사용자에게 모델 ID·JSON·lease 등 내부 용어를 노출하지 않는다.

### 탐색과 근거 선택 화면 계약

Space는 우측 상단에서 자료를 올리고 검색어가 없을 때 종류 탭 아래에서 바로 목록과 자료별 관리 메뉴를 제공한다. Admin과 Space의 인접한 작업 버튼은 8px 이상 간격을 두고 좁은 화면에 맞게 배치한다. 등록은 현재 화면에서 진행하며 검색 조건을 유지한다. PPTX 레퍼런스의 본문과 재사용 자료는 원본 슬라이드 단위로 묶고 개별 자료의 선택 순서를 보존한다. 검색 결과는 뉴스형 행으로 표시하고 각 자료는 독립된 문서 상세에서 연다. Studio의 관련 자료 탐색은 근거 단계의 추가 검색에 속한다. 기본 화면은 선택한 근거이며, 추가 검색 후보와 한 자료의 원문/비교 자료를 나란히 검토한다. 상단 별도 과거 자료 찾기 버튼이나 결과마다 긴 원문을 펼치는 배치는 사용하지 않는다. 근거 완료는 별도의 저장·확정 계약을 구현한 경우에만 표시한다.

근거 검토의 데스크톱 두 패널은 화면 높이에서 내비게이션과 하단 작업 패널 여백을 제외한 공간을 사용하며 각각 독립적으로 스크롤한다. 900px 이하에서는 후보 목록을 원문 상세로 전환하고 페이지 전체로 읽는다. 목록과 원문에 중첩 스크롤을 만들지 않으며, 목록 복귀 시 검색 조건·선택 상태·스크롤 위치·키보드 초점을 유지한다.

### 실제 생성 화면

근거 단계 끝에서 선택한 추가 근거 수와 현재 원본만 사용하는 경우를 구분하고 명시적으로 확인한다. 템플릿 단계는 실제 미리보기 갤러리와 기본 디자인 선택으로 구성한다. 생성 단계는 목차 선택·제목·선택적 추가 요청을 별도 설정 버튼 없이 본문에 통합하고, 실제 처리 상태·생성 이력·다운로드를 제공한다. 생성 폼에는 수동 레퍼런스 추가 버튼을 두지 않는다. 생성 과정이 선택한 목차의 맥락에 맞는 그림·차트·장표를 찾아 활용하는 것을 목표로 하며, 실제 자동화 완료 여부는 개발 문서에 구분한다. 완성된 결과의 편집기 참고 자료 탭에서는 사용자가 직접 자료를 바꿀 수 있다. 일반 사용자가 생성 모델을 고르는 입력란은 제공하지 않고 서버가 관리 설정의 활성 LLM을 선택·고정한다. 사용할 연결이 없으면 입력을 보존하고 관리자 확인을 안내한다. 최초 생성은 목차와 입력란을 바로 보여주며, 결과가 있으면 편집 캔버스를 먼저 배치하고 추가 생성 폼을 그 아래에 둔다. AI/직접 작성 탭 대신 목차 행에 작은 회색 연필·＋ 아이콘을 둔다. 연필은 제목과 순서 수정, 대목차의 ＋는 하위 중목차 추가를 제공하며 체크박스와 별도 버튼으로 구성한다. 저장은 리비전 조건을 검사하며 기존 PPT를 재생성하지 않는다. PC 결과 영역은 좌측 장표 목록·중앙 실제 미리보기·우측 내용/참고 자료 패널, 모바일은 가로 썸네일·장표·아래 정보 패널로 구성한다. 초안과 최종 PNG를 구분하며 상세 내용·발표 메모·정확한 출처는 우측 작업 탭에서 확인한다. 새 버전 생성은 명시적 명령으로 이전 파일을 보존한다. 제품 AI와 대화 탭은 선택한 장표의 텍스트·이미지·차트·도형·배치 범위를 고정하여 수정안을 보여주고 명시적 적용 후 새 PPTX 버전을 만든다. 객체 탭에서 이미지 등록·차트 수치·선택 범위를 다루며 직접 드래그 도구는 아직 표시하지 않는다.

Admin은 초기 CLI 토큰 또는 현재 실행 중 변경한 토큰을 요구한다. 로컬 사이드 메뉴의 일반 설정에서 토큰을 변경할 수 있고, 적용 전 영향 범위를 확인한다. 변경 후 새 토큰으로 재진입하며 재시작 시에는 새 CLI 난수 토큰으로 초기 진입 절차를 반복한다. Home·Studio·Space는 이 입력을 요구하지 않는다.


### Studio 진행 표시와 작업 패널

Stepper는 생성·편집을 포함한 모든 Studio 단계에서 항상 보이며 전역 메뉴 아래에 고정한다. 진행 표시를 disclosure에 넣어 숨기지 않는다. 모바일에도 여섯 단계를 표시한다. 장표 화면은 좌측 목록·중앙 캔버스·우측 작업 패널로 구성하며 양쪽 패널을 독립적으로 접고 펼칠 수 있다. 접기 버튼은 숨겨지는 영역 밖에 남고, 접어도 선택·탭·작성 초안을 유지한다. 본구현의 우측 패널은 실제 제공되는 내용·메모 및 참고 자료를 표시한다.


### 간결한 모델 연결 편집

연결 폼은 주소 → API Key → 모델 선택 순서로 표시하며 키보드 탐색도 같은 순서를 따른다. 저장된 주소·API Key 교체는 모델 선택 위의 ‘연결 주소·인증 변경’으로 펼치고, 표시 이름·시간 제한 등은 추가 연결 설정에 둔다. 새 연결에는 주소와 인증 입력을 바로 제공한다. 입력·작업 도움말은 앱 공통 `.field-hint`에서 0.8125rem(기본 13px), 1.5 줄높이와 muted 색상을 적용한다. Home·Studio·Space·Admin에 직접 접속해도 동일하며 파일 형식·태그 안내도 이 스타일을 사용한다. 반복되는 Provider 프로토콜·설정 버전 안내를 요약에서 제외한다. 연결 저장 결과는 폼에 표시하고 중복 토스트를 생성하지 않는다. 공통 토스트는 body에 하나의 호스트로 표시하며 최신 알림 한 장만 보여준다. 작업 패널이 있으면 실측 높이만큼 위에 배치한다.
